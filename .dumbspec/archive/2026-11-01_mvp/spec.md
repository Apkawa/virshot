# 2026-11-01_mvp: MVP VIRShot по спеке

**Created:** 2026-11-01T16:16:37+03:00

## Scope
В scope — ровно MVP из `docs/spec.md` §2 (:17-28):
1. Глобальные клавиатурные хоткеи (system-wide hook) + модель биндов: на каждое действие два поля (Основное/Дополнительное), в MVP каждое — клавиатурный комбо; поле кнопки геймпада — зарезервированный слот (`pad = null`, нотация canonical имя `gilrs::Button` / `unknown:<N>` — при интеграции геймпада), срабатывание по любому заполненному полю (OR), debounce ~250 мс.
2. Захват: весь экран (монитор foreground-окна, fallback — primary) и окно (foreground-окно независимо от z-порядка; «no active window» → ошибка); форматы png/jpg/webp (+quality); шаблон имени с токенами `%Y %y %mo %d %H %M %S %iso %t %n %ext`; санитизация; валидация шаблона (только относительный путь от `save_path`, без `..` и абсолютных путей); анти-коллизии (`-2`, `-3`, `%n` через скан папки); автосоздание подпапок; сохранение в отдельном потоке.
3. Оверлей-тост: одно окно, новый тост заменяет текущий; transparent, без декораций, always-on-top, mouse passthrough; fade ~250 мс, hold `duration_ms` (default 2000, ошибки ~3000); 4 угла + offset ~16 px; `on_all_monitors` (default true); ошибки видны даже при `enabled = false`.
4. Окно настроек: ~720×520, 3 вкладки (General / Hotkeys / Overlay), кнопка Apply (пишет `config.toml`, применяет live; закрытие без Apply — сброс); закрытие по X → hiding in tray; UI English.
5. Системый трей: built-in иконка; левый клик → настройки; меню Take screenshot / Settings / Exit; выход только из меню.
6. Конфиг `config.toml` по конвенциям OS (`%APPDATA%\virshot\config.toml` / `~/.config/virshot/config.toml`), авто-дефолт при первом запуске, битый конфиг → лог + дефолты.
7. Headless-подкоманда `virshot shot [--window] [--out] [--format]` + флаги `--config --log --log-level --version --help`; путь файла в stdout; exit 0/1; лог `virshot.log` рядом с конфигом.
8. Single-instance guard.
9. Non-functional (§5): binary < 10 МБ, RAM < 30 МБ в фоне, CPU < 1% idle, без сети, fault-tolerance (ошибка → лог + тост, не падение).
Тесты и поставка (§10): unit (шаблон, санитизация, валидация, конфиг), E2E headless в `tests/`, Windows-приёмка вручную (чеклист в чат), portable zip (`virshot.exe` + README).

Out of scope (спека §30-40 + Scope guard): реализация rect-захвата (слоты в конфиге/UI зарезервированы, неактивны), видео/Replay Buffer, встроенный редактор, exclusive full screen, autostart, custom tray icon, i18n, macOS, интеграция с геймпадом (слот зарезервирован: `pad` в конфиге, поле бинда в UI; будущая реализация — цикл опроса HID через `gameinput.dll` (`RawGameController`, diff состояний кнопок, метки `GetButtonLabel`) на Windows + `gilrs` на Linux; Stage 7 в плане помечен DEFERRED).

## Approach
Развиваем PoC поверх существующего кода, с реструктуризацией по правилу «один модуль = один файл»:
- `src/main.rs` — только wiring: clap-CLI, выбор режима (GUI vs headless `shot`), запуск потоков.
- Модули: `config` (schema + load/save/defaults + путь по OS), `template` (токены, санитизация, валидация, коллизии), `capture` (xcap: monitor/window + foreground-логика + own-window exclusion + encoding png/jpg/webp), `bindings` (модель биндов key-combo, pad-поле зарезервировано, debounce, статусы регистрации), `hotkeys` (обёртка выбранного crate глобальных хоткеев), `logging` (tracing + file appender), `overlay` (тост), `settings` (GUI-вкладки, Apply), `tray` (tray-icon + меню), `instance` (single-instance guard), `app` (event-loop wiring, каналы).
- Threading по §6: main = eframe loop + tray events (MenuEvent::receiver) + overlay timer; input-поток = hotkey crate → команда в канал main (геймпад-поток — цикл опроса HID через `gameinput.dll` — добавляется при интеграции геймпада, вне MVP); capture-поток = команда → захват → save. Без shared `Mutex` — owned values/каналы.
- Overlay: egui multi-viewport (`ViewportBuilder::with_transparent` + `with_mouse_passthrough`, `Context::show_viewport_deferred`) — research-факты подтверждают наличие API (egui 0.37); если на Windows не работает passthrough/transparent — fallback на native-окно (решается на stage оверлея).
- Пути конфига: ручной env-handling (Windows — `APPDATA`, Linux — `XDG_CONFIG_HOME`/`HOME`) без нового crate.
- Форматы jpg/webp: явный crate-dependency `image` с features `jpeg`,`webp` (сейчас locked `image` тянет только png+tiff) — требует подтверждения пользователя.
- Глобальные клавиатурные хоткеи: crate не выбран — deep research выносится в отдельный stage плана (кандидаты будут оценены там), добавление crate — после подтверждения пользователя.
- Single-instance guard: механизм определяется на research-stage (lock-файл vs OS-примитив vs crate); `unsafe` запрещён, поэтому crate с named-mutex внутри допустим только с явным approval.
- Non-functional бюджеты: измерить после внедрения GUI (size, RAM, CPU); при перерасходe — обрезать features eframe (accesskit и т.п.) без новых зависимостей.
- UI-строки English (спека :126); токены/keys в конфиге — canonical имена: `%mo` = 2-значный месяц (из дефолтов `Full%y-%mo`), кнопка геймпада — при интеграции (вне MVP) — canonical имя варианта `gilrs::Button` (South, East, …) либо `unknown:<N>` — raw-номер кнопки (Windows gameinput-бэкенд: метка из `GetButtonLabel`, UI capture-режим «нажмите кнопку» пишет номер); клавиша — имя key из выбранного hotkey crate. Ограничения геймпад-интеграции: геймпады, которые GameInput классифицирует как Gamepad (Xbox Series), отдают только канонические 14 кнопок — Share на них может не приходить (проверка на Windows-железе); Xbox Game Bar перехватывает Share (побочный запуск Game Bar — документировать в README); номера raw-кнопок стабильны только внутри одной модели геймпада.
- Тесты: unit TDD по модулям (детерминированно: `DateTime` инжектится); E2E `tests/` (no-TDD) про built binary headless; зелёные на обоих таргетах (`cargo test`, `cargo test --no-run --target x86_64-pc-windows-gnu`).

## Constraints
- Rust stable (1.99.1), edition 2024; targets: Linux native + `x86_64-pc-windows-gnu` (MinGW-линкер в `.cargo/config.toml`).
- `#![forbid(unsafe_code)]` добавить в crate root (сейчас отсутствует).
- Зависимости фиксированы AGENTS.md; новые crate/native-package/toolchain — только с явного подтверждения. **Геймпад-бэкенды вынесены из MVP (v4, 2026-11-02): dep `gilrs` и target-scoped `windows` удалены из Cargo.toml; при интеграции геймпада возвращаем с approval пользователя: Windows — direct dep `windows` crate `RawGameController` (approved 2026-11-01, в lock уже есть транзитивно через winit), Linux — `gilrs` с `default-features = false, features = ["wgi"]` (без features — compile_error на любом таргете)**; `tray-icon` — `default-features = false, features = ["ksni"]`.
- Одна модуль = один файл; модульные тесты в том же файле; naming `<unit>_<scenario>_<expectation>`; `cargo fmt` владеет форматированием; commits — Conventional Commits.
- Ошибки — typed enums (`thiserror`), без `unwrap()` вне tests/init; loop логирует и продолжает; время инжектится в producers.
- В sandbox: `./cargo.sh` (CARGO_HOME в `./.cache`); rusty-hook CLI не в PATH → pre-commit gate молча скипается, верификация явно: `./cargo.sh check && ./cargo.sh test && ./cargo.sh fmt && ./cargo.sh clippy -- -D warnings`; scratch — только `./.tmp/`.
- PoC: `src/main.rs` (219 строк) с inline-модулями и hardcoded `./.tmp/screenshots`; declared-but-unused deps (eframe/egui/clap/tray-icon/serde/toml/tracing/thiserror) уже в Cargo.toml.
- Linux-цепочка xcap требует установленных dev-пакетов (установлены); Wayland-захват только под работающим compositor (WSLg); геймпады на этой хосте не обнаружены.
- Spec §11-12 (limitations): exclusive full screen не поддерживается; Win11 PrintScreen может перехватываться Snipping Tool.

## Open questions
- Выбор crate глобальных хоткеев (нужен system-wide hook; требует approval на новый crate) — решается на research-stage.
- Механизм single-instance guard (без unsafe) — решается на research-stage; если crate — approval.
- tray-icon на Linux в WSLg (SNI требует D-Bus) — feasibility проверяется на tray-stage; финальная приёмка — Windows.
- Итоговая схема конфига (спека помечает её черновой, :175-176) — финализируется вместе с выбором hotkey crate.
- Win11 перехват PrintScreen — поведение проверяется на Windows-приёмке; в MVP — статус регистрации в UI + лог.
