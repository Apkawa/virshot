## 7 decisions recorded during spec review (2026-11-03)

- **Library form:** `crate/gamepad` = standalone crate directory `crates/gamepad/` mirroring the poc layout nearly 1:1 (per user wording "crate/gamepad"): `src/gameinput.rs` (shim, `#![allow(unsafe_code)]` exception), `src/layout.rs`, `src/lib.rs` (public API facade), `examples/` console tester, `vendor/GameInput.h`, own Cargo.toml (zero deps), NOT a workspace member (root manifest has no `[workspace]`; virshot consumes it via path dependency).
- **No `windows` crate needed:** the poc shim proves GameInput works with zero deps; the "windows crate RawGameController" plan in AGENTS.md/docs/spec.md is superseded by the hand-written shim (no new dependency, no approval needed).
- **unsafe:** `#![forbid(unsafe_code)]` stays at virshot crate root (src/main.rs); the gamepad crate root uses `#![deny(unsafe_code)]` with the single `gameinput.rs` module exception, same pattern as the poc and the extract-branch precedent.
- **Linux backend:** out of scope. The crate compiles on Linux (layout + API surface stub/no-op), virshot integration is `#[cfg(windows)]` only.
- **Dispatcher + 50 ms poll kept** exactly as in poc (minimal changes per user request); the example app is the poc main.rs rebuilt on the library API.
