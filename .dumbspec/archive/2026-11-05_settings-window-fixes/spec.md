### Доработки v3 (2026-11-06) — обход PrintScreen через временную хоткей-пробу

- [x] Причина зафиксирована (`.tmp/printscreen-report.md`): для `VK_SNAPSHOT` Windows не отправляет `WM_CHAR`/`WM_DEADCHAR`; `winit 0.30.13` в `platform_impl/windows/keyboard.rs::process_message` (`WM_KEYDOWN | WM_SYSKEYDOWN`) откладывает событие до CHAR-сообщения и теряет его на следующем keydown (`*event_info = None`). Поэтому `egui` не получает `Event::Key { key: PrintScreen }` и строка не меняется до `Esc`. Это ограничение ОС, не баг нашего кода; апстрим-фикса в winit после 0.30.13 нет.
- [x] `src/hotkeys.rs` — временная «проба» клавиш, которые Windows не доставляет в egui: на время захвата бинда (пока live-хоткеи paused) регистрируются комбы из расширяемого списка проблемных клавиш (`PrintScreen`, `ScrollLock`, `Pause`) — bare + `Alt`/`Ctrl`/`Shift` (+`Alt+Shift`, `Ctrl+Shift`), без `Win` (в захвате недостижим). Событие пробного комбо НЕ запускает скриншот: слушатель записывает нажатие (код + модификаторы) в общий слот и будит eframe (`request_repaint`), GUI забирает его в `logic`. Проба работает только на Windows (`cfg(windows)`); на Linux клавиши доставляются обычно, проб — нет. Ошибка регистрации пробного комбо — WARN (клавиша остаётся unbinnable), краша нет.
- [x] `src/bindings.rs` — нотация: `parse_key` принимает `ScrollLock` (и другие имена проб), чтобы бинд, записанный пробой, парсился обратно и перерегистрировался; round-trip закрепляется тестом.
- [x] `src/gui.rs` — старт захвата клавиши: `controller.pause()` + старт проб; конец захвата (commit/cancel/clear): стоп проб перед `controller.restore()`. В `logic` — `take_probe_press()`: если `.press` есть и активен захват клавиши, записывается `key`/`mods` этой строки (`pad` остаётся), захват завершается как обычный commit. Проба не участвует в дубликатах/предупреждениях.
- [x] Тесты (sibling-файлы, чистая логика): `src/hotkeys.tests.rs` — список пробных комбо детерминирован и не пересекается с действиями, пробное нажатие не диспатчится как действие, `take_probe_press` забирает ровно одно нажатие; `src/gui.tests.rs` — commit-семантика пробного нажатия (key+mods пишутся, pad остаётся), стоп проб на cancel/clear; `src/bindings.tests.rs` — round-trip имён проб.
- [x] `docs/spec.md` — §4.4: обход проблемных клавиш через временную хоткей-пробу на Windows (в т.ч. PrintScreen), §4.1/§9: почему пробa только на Windows и что Snipping Tool перехватывается только на время захвата; список проблемных клавиш как расширяемый.

## Constraints

- Один модуль = один файл; правки UI живут в `src/gui.rs` (+ sibling `gui.tests.rs`).
- Никаких новых crates.io зависимостей и новых native пакетов (набор зависимостей зафиксирован в `AGENTS.md`); `crates/gamepad` остаётся hand-written COM shim без unsafe кроме существующего.
- Публичный контракт сохранения не меняется: запись на диск, перерегистрация хоткеев и публикация настроек происходят только в `apply() :652-676`.
- Оверлей-чипы продолжают краситься из `logic` (`overlay_host.update(ctx) :1140`); `with_transparent(true)` + alpha-0 `clear_color` остаются (иначе чипы/трей-тосты ломаются).
- UI-текст — английский (`docs/spec.md §4.4`); бюджет (exe <10 MB, RAM <30 MB, CPU <1% idle) сохраняется.
- Гейт: `./scripts/check.sh` после партий правок; `./scripts/check_full.sh` на границах стадий; Windows-компиляция тестов `./cargo.sh test --no-run --target x86_64-pc-windows-gnu`.
