# 2026-11-07_video-capture-crate: изолированный крейт записи видео

**Created:** 2026-11-07T01:18:52+03:00

## Scope

**In scope:**
- Новый изолированный крейт `crates/video-capture` — запись видео экрана под Windows
  поверх крейта `windows-capture` (Media Foundation: NVENC/AMF через hardware-accelerated MFT).
- ПараметрыCaptureConfig: encoder, codec (h264 / hevc), bitrate (режимы + битрейт),
  resolution (720p / 1080p / Full), fps (30 / 60), replay_buffer (0..600 сек),
  audio (none / system / mic / both).
- Кольцевой буфер кадров в памяти (реализуем сами — библиотека его не даёт): при
  `replay_buffer > 0` capture-поток постоянно копает кадры; по «старт» в файл
  попадают предыдущие N секунд, затем запись продолжается до «стоп».
- Тестовый egui-пример `crates/video-capture/examples/capture_demo.rs`: путь к файлу
  (по умолчанию `%USERPROFILE%\Videos\test.mp4`), все параметры, кнопка запись/стоп,
  логирование в stdout/stderr (tracing).
- Переключатель кольцевого буфера (правка v2): методы публичного API
  `Recorder::enable_replay(seconds)` / `Recorder::disable_replay()` рядом со start/stop
  + кнопка «Буфер» в UI. Выключение освобождает уже собранные в буфере кадры;
  включение прогревает буфер только с этого момента.
- Пауза ~1с при старте записи (правка v2): команда Start ставится в очередь до
  запуска capture-потока; кадры до появления энкодера не сдвигают pacing-таймстамп,
  поэтому первый кадр после энкодера всегда отправляется.
- Смысл буфера — пре-ролл в файл (правка v3): при `replay_buffer = N` секунд файл
  начинается с последних N секунд ДО нажатия «Запись» и дальше пишется live-запись,
  т.е. длина файла ≥ N секунд при полностью наполненном кольце. Snapshot кольца
  подаётся в энкодер на старте (`ring.take()` в `start_recording`) — это уже
  реализовано; фиксируем как контракт + оговорка: при редкой доставке кадров окно
  короче N (кадров меньше, чем capacity).- Буфер включается отдельно от записи (правка v3): в демо «Буфер» без активной записи
  создаёт сессию захвата только под кольцо (`Recorder::new` + `enable_replay(seconds)`),
  чтобы пре-ролл копился до любой записи; «Запись» при живой сессии использует её
  (`start(path)` в очереди), а не создаёт новый `Recorder`.
- После «Стоп» буфер включается обратно (правка v3): кольцо снова наполняется, как
  только энкодера нет и ёмкость > 0 (во время записи кольцо пустое — экономия RAM);
  явно выключенный буфер остаётся выключенным.
- `replay_buffer = 0`: конец записи освобождает захват (правка v3): после записи файла
  capture-сессия закрывается (`capture_control.stop()`), фасад помечает сессию
  освобождённой и на последующие команды отвечает `NotConfigured`. Сам индикатор WGC
  не правим (см. Out of scope) — освобождение сессии только заметно по его исчезновению.
- Пре-ролл не фризит запись (правка v4): выгрузка кольца в энкодер выполняется
  асинхронно — отдельный поток-писатель владеет `VideoEncoder`, capture-колбэк только
  кладёт кадры в очередь и возвращается, поэтому в файле нет «замороженного» кадра на
  моменте нажатия «Запись» (symptom: 10с буфер → видимый freeze в записанном ролике).
- Выключение буфера освобождает захват (правка v4): если активной записи нет,
  `disable_replay()` (кнопка «Буфер» off) закрывает capture-сессию на следующем кадре —
  индикатор гаснет, дальнейшие команды отвечают `NotConfigured`; при активной записи
  освобождение происходит после «Стоп» (уже реализовано).
- Публичное API по типам параметров (правка v5): разрешение — произвольная высота
  `u16` (`Resolution::Height(u16)`, хоть 160) плюс `Full` (нативный размер экрана);
  `ScaleFilter::Triangle` переименовывается в `ScaleFilter::Bilinear` (реализация —
  separable bilinear, пользовательский label уже «Bilinear»); `fps: u8`. Нерабочие
  опции удаляются целиком: `EncoderKind` (nvenc/amf/x264 — библиотека не выбирает
  энкодер, выбор невозможен) и `BitrateMode` (cbr/cqp/crf — реально только CBR через
  `bitrate_kbps`). `codec` остаётся (H264/HEVC реально применяются), `audio` остаётся
  заглушкой — решение по аудио за пользователем.
- Windows-проверка — вручную пользователем; на Linux крейт должен компилироваться.

**Out of scope:**
- Linux-бэкенд (GStreamer+VA-API) — не делаем.
- Интеграция в virshot — изолированно, root-крейт не трогаем.
- Запись микрофона (mic) — todo, не реализуем.
- Индикатор захвата Windows (жёлтая рамка) — штатное поведение ОС при открытой
  capture-сессии, по указанию пользователя (2026-11-07) не правим.
- Прямая зависимость `windows` для `VideoEncoder::new_from_stream` (запись в
  `InMemoryRandomAccessStream`) — не добавляем: это новый crates.io пакет, требует
  отдельного одобрения, и всё равно не даёт кольцевой буфер (см. таблицу).

## Approach

- **Зависимость:** `windows-capture = "2.0.1"` (MIT) под
  `[target.'cfg(windows)".dependencies]` + все use-сайты за `#[cfg(windows)]`
  (на Linux крейт не компилируется — проверено: 16 ошибок в `windows-future`).
  Одобрено пользователем. Транзитивно добавляет только 3 пакета:
  `windows-capture`, `rayon`, `rayon-core` (цепочка `windows 0.62.2` уже в lock
  через `xcap`); feature-унификация расширяет features `windows` workspace-wide
  (compile-time рост, новых пакетов нет).
- **Архитектура:** один capture-поток (`GraphicsCaptureApiHandler::start` takeover'ит
  поток) с кольцевым буфером `VecDeque<(timestamp_100ns, BGRA-кадр)>`; команды
  старт/стоп из UI через канал (channel, не `Arc<Mutex>`); `VideoEncoder` создаётся
  на «старт», replay-кадры подаются через `send_frame_buffer`, live-кадры —
  `send_frame`/`send_frame_buffer`, на «стоп» — `finish()`.
- **Item:** `Monitor::primary()` (full-desktop). Picker не используем.
- **Разрешение (v5):** `Resolution::Height(h)` — высота `u16`, ширина выводится из
  aspect'а экрана (`native_w * h / native_h`, floor, ≥1); `Full` = native-размер
  монитора. Высота выше нативной не апскейлится (остаёт native, как сейчас), высота 0
  отвергается (`Recorder::new`/`recording` → `CaptureError::NotConfigured`, нулевой
  размер нерабочий: resize/flip дают пустые байты, D3D-текстура 0×0 невозможна).
  Down-scale делает CPU-resize BGRA (библиотека не даунскейлит — crop/black-pad),
  подача через `send_frame_buffer`; `Full` (native == target) — без ресайза.
- **fps (v5):** `fps: u8` → `frame_rate(u32)` (знаменатель 1) +
  `MinimumUpdateIntervalSettings::Custom(1/fps)` + pacing по timestamps.
- **MP4:** контейнер MPEG4 (`ContainerSettingsSubType::MPEG4`), muxing делает сам
  `windows-capture` (Media Foundation MediaTranscoder) — сторонний muxer не нужен.
- **unsafe:** не нужен — у `windows-capture` нет `pub unsafe fn`; крейт
  `#![forbid(unsafe_code)]`.
- **Жизненный цикл сессии (v3, «как проще»):** пре-ролл берётся из кольца один раз на
  старте (`ring.take()` → `send_frame_buffer`), во время записи кольцо пустое, после
  Stop наполняется снова при ёмкости > 0. «Дописывать буфер в файл после Stop» не
  делаем: те кадры уже в файле, дублировать их не нужно, и с нулевым буфером такой
  схемы всё равно не существует. При ёмкости 0 Stop закрывает сессию: движок ставит
  флаг освобождения, на следующем кадре вызывает `capture_control.stop()` и отдаёт
  событие `CaptureReleased`; фасад помечает recorder освобождённым, и start/stop/
  enable_replay после этого отвечают `CaptureError::NotConfigured` (как после shutdown).
- **Писатель энкодера отдельно от capture-потока (v4, «асинхронно»):** `VideoEncoder`
  `Send` (не `Sync`), значит его можно переместить в отдельный поток-писатель. Start:
  ring-snapshot + энкодер переходят в писатель, который подаёт пре-ролл, потом live-кадры
  из очереди. Capture-колбэк при записи делает только копию BGRA-буфера и `send` в
  очередь (bounded; при отставании писателя кадры сбрасываются с логом) и сразу
  возвращается — колбэк больше не стоит на сотнях `send_frame_buffer`, freeze исчезает.
  Порядок таймстампов сохраняется FIFO (пре-ролл старше live-кадеров). Acks
  (`RecordingStopped` / `CommandFailed`) пишет писатель в тот же event-канал; `stop()`
  и `finish()` происходят на писателе, фасад ихpoll'ит как раньше. GPU fast-path
  (`send_frame(surface)`) при записи не используется — кадры передаются буферами.
- **Не реализуемые параметры** помечаются в API (`*NotSupported` варианты /
  disabled-контролы в UI) и в спеке — без workaround, по указанию пользователя.

### Реализуемо vs «не получилось» (по research.md)

| --- | --- |
| encoder: nvenc / amf / x264 | **удалено из API (v5)** — `windows-capture` не выбирает энкодер, MF сам решает (HW включён hard-coded); выбора и наблюдения нет, поэтому `EncoderKind` вынесен из публичного API целиком |
| codec: h.264 | реализуемо — `VideoSettingsSubType::H264` |
| codec: hevc | реализуемо — `VideoSettingsSubType::HEVC` |
| codec: h.265 | = hevc (отдельного значения в API нет) — alias |
| bitrate: cbr | реализуемо — `bitrate(u32 bps)` (MF `MF_MT_AVG_BITRATE`); в API остаётся только `bitrate_kbps` |
| bitrate: cqp / crf | **удалено из API (v5)** — `BitrateMode` не передавался в библиотеку (реально только CBR, `ICodecAPI` не используется), опция удалена целиком |
| resolution (высота u16 + Full) | реализуемо через CPU-resize (`image` crate, уже одобрен) + native Full |
| fps (u8) | реализуемо — `frame_rate` + pacing; гарантию константности MF не даёт |
| replay_buffer 0..600 | реализуем сами (ring-буфер в памяти, лимит по числу кадров = seconds×fps) |
| replay_buffer как сжатый поток (H.264/HEVC-пакеты в RAM вместо сырых кадров) | **не получается средствами библиотеки** — `VideoEncoder` принимает только несжатый BGRA (`VideoEncodingProperties::CreateUncompressed`, encoder.rs:882-887), закодированные пакеты наружу не отдаются (нет `IMFSourceReader`/`GetNextSample`/callback), а `InMemoryRandomAccessStream` не умеет вытеснять старые байты (только Size/Seek/Close) → окно «последние N секунд» невыразимо. Отмечено нереализуемым, без workaround. |
| enable/disable кольцевого буфера в рантайме | реализуем сами (команда в capture-поток, пересборка/слив ring) |
| audio none | реализуемо — `AudioSettingsBuilder::default().disabled(true)` |
| audio system | **не получается средствами библиотеки** — loopback/WASAPI-захвата нет; API принимает PCM-буферы, но источник звука требует новой зависимости (cpal) или unsafe-шима (запрещён). Помечается не реализованным; `both` = `none` до появления mic/system. |
| audio mic | todo, не реализуем |
| MKV/WebM | не получается (контейнеры MF: MP4/AVI/…) — в scope только MP4 |

## Constraints

- Rust stable 1.99.1, edition 2024; `windows-capture` edition 2024, resolver 3
  (Cargo ≥1.87) — совместимо.
- МинGW cross-build проверен: `cargo check --target x86_64-pc-windows-gnu` → exit 0
  (raw-dylib, import-libs не нужны).
- Linux: `cargo check` крейта без cfg-gating → fail; gating обязателен.
- `VideoEncoder`: `Send` но не `Sync` → один encoder на capture-поток.
- Память ring-буфера: сырые BGRA-кадры на выходе энкодера. На экране 1680x1050:
  720p → 1152x720 = 3,317,760 Б/кадр; 1080p/Full → native 1680x1050 = 7,056,000 Б/кадр.
  60s@30fps ≈ 5.97 GB (720p) / 12.70 GB (native); @60fps — вдвое. `MAX_REPLAY_SECONDS
  = 600` допустим ~59–126 GB RAM, поэтому: ring не пополняется, пока идёт запись
  (содержимое уже на диске), и UI показывает честную оценку.
- `Recorder::new` открывает capture-сессию (StartCapture), поэтому индикатор ОС виден
  и после «Стоп» (сессия закрывается только в Quit/Drop) — штатное поведение.
  Исключение (v3): при `replay_buffer = 0` (кольцо выключено) «Стоп» закрывает сессию —
  capture-поток останавливается, и индикатор пропадает; при буфере > 0 сессия
  остаётся открытой, потому что она нужна для наполнения кольца. Исключение (v4):
  выключение буфера без активной записи закрывает сессию сразу (на следующем кадре) —
  индикатор гаснет без записи.
- Таймстампы аудио в crate игнорируются (monotonic audio clock) — актуально только
  при реальном audio-источнике; сейчас audio=none.
- Размеры в библиотеке — `u32` (`VideoSettingsBuilder::new(w, h)`, `SetHeight`, D3D
  текстура, `Monitor::height()`), поэтому `u16`-высота проходит без ограничений;
  `send_frame_buffer` ничего не валидирует — проверки размера остаются в крейте.
  Target фиксируется при создании `Recorder` (нативный размер читается там же),
  смена высоты требует нового recorder.
- Проектные gates: `./scripts/check.sh` (Linux), `./cargo.sh test --no-run --target
  x86_64-pc-windows-gnu` (Windows-компиляция), `#![forbid(unsafe_code)]`.
