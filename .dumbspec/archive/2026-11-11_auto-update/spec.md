# 2026-11-11_auto-update: Автоматическое обновление

**Created:** 2026-11-11T13:12:19+03:00

## Scope

В scope:
- Настройки в секции **General** окна настроек, сгруппированные под заголовком-секцией **«Обновление»** (не отдельная вкладка):
  - метка **«Проверять обновления»** над дропдауном: `никогда` / `1h` / `1d` / `1w`
  - кнопка **«Проверить обновления»** под дропдауном — принудительная проверка (работает и при `никогда`)
  - дропдаун канала: `stable` / `nightly`
  - чекбокс «автоматически устанавливать»
- Фоновая проверка при запуске **и по интервалу внутри процесса** (`1h` / `1d` / `1w`):
  - `stable` → metadata последней stable-релизы, `nightly` → prerelease с tag `nightly`
  - сравнение `version` и `commit_sha` с текущей сборкой
- Реакция на обнаруженное обновление:
  - автоустановка выключена → строка/кнопка «Доступно обновление» в General tab + тост → окно с описанием изменений и кнопками «Обновление» / «Отмена»
  - автоустановка включена → сразу процесс установки
- Процесс установки (crate `self_replace`): скачивание архива во временную папку, проверка sha512 по ассету `release.yaml`, распаковка бинарника во временную папку, `self_replace::self_replace(...)`, **немедленный перезапуск**
- Установка на **обеих платформах**: Windows (zip) и Linux (tar.gz)
- Очистка leftover-файлов обновления (`*.old`, скачанные архивы) при каждом старте
- Правка `docs/spec.md`: новый раздел автообновления + корректировка §5 (сетевые запросы) и §10 (поставка без автообновления)

Out of scope:
- Инсталлятор, diff/partial updates, отдельный updater-процесс, rollback
- GPG/подписи: доверие = HTTPS с github.com + sha512 из `release.yaml`
- ARM64 (`aarch64-*`) — уже отложен в AGENTS.md
- Обновление по требованию из tray-меню, proxy/token-настройки, автообновление в одноразовом CLI-режиме `virshot shot`

## Approach

- **Модули (один модуль = один файл):**
  - `src/update.rs` — metadata релиза, парсинг `release.yaml` (`serde-saphyr` + `serde`), решение «нужно ли обновление», планирование по интервалу; чистые функции сравнения тестируются напрямую.
  - `src/update_notes.rs` — fetch тела релиза (`body`) из GitHub API для окна описания; вызывается лениво при открытии окна, не при фоновой проверке.
  - `src/update_install.rs` — скачивание архива во временную папку, проверка sha512, распаковка, `self_replace`, перезапуск; там же `cleanup_leftovers()`.
  - `src/gui.rs` — контролы в General tab, строка «Доступно обновление», окно обновления (отдельный egui-viewport, как About), тост при обнаружении.
  - `src/main.rs` — шаг cleanup leftover в startup sequence + запуск фоновой проверки.
- **Источник metadata:** ассет `release.yaml` по download-URL, без GitHub API:
  - stable → `https://github.com/Apkawa/virshot/releases/latest/download/release.yaml` (GitHub отдаёт redirect на последний non-prerelease релиз)
  - nightly → `https://github.com/Apkawa/virshot/releases/download/nightly/release.yaml`
  Парсинг — `serde-saphyr` (ассет `release.yaml` — YAML с синтаксисом `key: value`; строгий `toml` его отвергает). Crate уже в `Cargo.lock` транзитивно через `rust-i18n`, поэтому добавляется только строка-объявление в `Cargo.toml`: **ноль новых пакетов** и, по замеру, +14 KB на Linux / +22 KB на windows-gnu release. JSON-деп не нужен.
- **Описание изменений:** `GET https://api.github.com/repos/Apkawa/virshot/releases/latest` (stable) и `/releases/tags/nightly` (nightly) → поле `body` (git-cliff notes), рендер через `egui_commonmark` (уже в зависимостях). Fetch только при открытии окна — анонимный лимит GitHub API (60 req/h) не затрагивается фоновой проверкой. При неудаче fetch окно показывает summary из `release.yaml` (version, releaseDate, commit_sha) + ссылку на страницу релиза (`webbrowser` через eframe `links`).
- **Сравнение (решение пользователя от 2026-11-12):** обновление предлагается, если `release.yaml.releaseDate` **новее** времени локальной сборки (`build::BUILD_TIME_3339`, UTC) **или** `release.yaml.version` **выше** локальной `build::PKG_VERSION`. `commit_sha` больше не триггер — он остаётся только в описании релиза и в summary-фallback окна. `-dev`-сборки (spec §4.6) проверку не пропускают (решение от 2026-11-11: dev — фактически nightly-сборка с master), но суффикс `-dev` в версии не сравнивается: для них решающим становится дата сборки, поэтому локальная dev-сборка новее опубликованного nightly → «Обновлений нет»; путь «переключиться с nightly на stable» остаётся (stable-релиз датирован позже → установка заменяет dev-бинарник релизным). Ограничение: ancestor-порядок коммитов не вычисляется, поэтому релиз, опубликованный позже локальной сборки, предложится даже если собран из более старых коммитов (downgrade-предложение принимается как известное поведение).
- **Сравнение даты и версии — без нового депа:** дата релиза парсится собственным читателем RFC 3339 (`YYYY-MM-DDTHH:MM:SS.mmmZ`, плюс offset-формат `±HH:MM`) в Unix-секунды; время сборки берётся из `build::BUILD_TIME_3339` (UTC). Версия сравнивается по числовым сегментам `major.minor.patch` (не лексически), недостающие сегменты считаются нулями. Непарсящаяся дата — Parse-ошибка проверки (не «обновление есть»).
- **Принудительная проверка (кнопка):** тот же `update::spawn_check`/тот же канал и тот же путь обнаружения, но независимо от `update_check` (в том числе `никогда`); кнопка активна только когда в полёте нет проверки; одновременно ровно одна проверка — нажатие, записанное пока слот занят, остаётся в очереди и выполняется при освобождении слота (нажатия не теряются); результат — строка/кнопка в General + тост (или автоустановка, если чекбокс включён). Кнопка не трогает дедлайн фонового интервала; исход принудительной проверки его не переоружает.
- **Видимость строки «Доступно обновление»:** строка в General гейтится **только наличием discovery** — интервал (`никогда`) и `-dev`-сборка её не скрывают, иначе принудительная проверка при `никогда` не показала бы результат.
- **Результат принудительной проверки рядом с кнопкой:** справа от «Проверить обновления» показывается исход последней принудительной проверки — при ошибке связи/лимитов (403 rate-limit, 404 до первого stable-релиза, network/timeout, битый YAML, нет артефакта для платформы) красный текст ошибки; при «обновлений не требуется» обычный текст «Обновлений нет». Пока проверка в полёте — статус не показывается. Текст ошибки остаётся verbatim английским (прецедент `capture::error_display` — сообщение `UpdateError`, не локализуемая строка); «Обновлений нет» — новый ключ локали на всех 6 языках.
- **Сброс предыдущего статуса:** любой исход проверки заменяет предыдущий результат — принудительная проверка на stable с 404 снимает удержанную discovery («Доступно обновление» не остаётся после переключения канала), исход «обновлений нет» тоже снимает. Ошибка **установки** discovery удерживает (как раньше — строка предлагает повтор), успешная установка снимает.
- **Расписание после Apply:** `apply()` пересобирает дедлайн по applied-интервалу (`никогда` → снять, смена интервала → новый дедлайн, `никогда` → scheduled → вооружить без перезапуска); проверка в полёте при Apply не отменяется. Дедлайн вооружается один раз на первом logic-проходе (startup-проверка spawn’ится до event loop), переоруживает только scheduled-исход.
- **Выбор файла под платформу:** элемент `files[]`, чей `type` = `x86_64-pc-windows-msvc` (Windows, включая локальные `-gnu` dev-сборки) или `x86_64-unknown-linux-gnu` (Linux). Ни одного неизвестного `type` не скачиваем.
- **Распаковка:** Windows — crate `zip` (минимальные features, deflate); Linux — объявленный `flate2` (уже в `Cargo.lock` транзитивно через `image`, ноль новых пакетов) + собственный читатель tar (одна запись-бинарник, с unit-тестами).
- **Проверка sha512:** base64-decode строки `sha512` (ручной декодер ~25 строк, без нового депа) → сравнение с `sha2::Sha512` digest скачанного файла; additionally сверка `size` из `release.yaml`. Digest 0.11 (sha2 0.11.1) **не** реализует `io::Read` — стриминг chunk-циклом (64 KiB, `h.update(&buf[..n])`), `finalize().as_slice()` = raw 64 байта; сверено byte-exact с `openssl dgst -sha512 -binary | openssl base64 -A`.
- **Фон:** plain `std` thread + `mpsc` (как `crates/toast`), результат дренируется в `App::logic`; планирование — дедлайн следующей проверки, вычисляется по инъектируемому времени, цикл держится живым существующим `request_repaint_after(500ms)` (в том числе при скрытом окне). Никакого async runtime.
- **Настройки:** `General.update_check: UpdateCheck` (`Never|Hour|Day|Week`, serde lowercase-строки — паттерн `Format`), `General.update_channel: UpdateChannel` (`Stable|Nightly`), `General.auto_install: bool`; дефолты `1d` / `stable` / `false` в `general_with_home()`. Запись только через `apply()` (draft/applied, `is_dirty = draft != applied`).
- **Перезапуск:** после успешного `self_replace` — освобождение `InstanceGuard` (удаление `<config>.lock`), `Command::new(std::env::current_exe())` spawn нового процесса, завершение старого с кодом 0. Порядок важен: новый процесс должен успеть взять lock, а pid-probe не должен видеть старый процесс.
- **GUI-less resident-режим** (`park_without_gui`): автоустановка выполняется (если включена); при выключенной автоустановке — только `tracing` (без окна и без тоста, т.к. нет overlay-хоста).
- **Очистка при старте:** удаление следов `self_replace` — `virshot*.__relocated__.exe` и `virshot*.__temp__.exe` в каталоге бинарника (на unix — `.<stem>.__temp__*`), `virshot*.__selfdelete__.exe` в `std::env::temp_dir()`, плюс наш архив/распакованный файл; `NotFound` молча игнорируется; ошибки логируются и не прерывают запуск.
- **Ошибки:** любая неудача (сеть, хеш, распаковка, replace) → `tracing::error!` + тост (`ToastColor::Danger`) в GUI-режиме; приложение продолжает работать; автоустановка не превращает ошибку в crash; следующая проверка — по интервалу.
- **Зависимости (approved 2026-11-11, verified на pinning-этапе):** `self-replace = "1.5.1"`, `ureq = { version = "3.5.1", default-features = false, features = ["rustls"] }`, `sha2 = { version = "0.11.1", default-features = false }`, `zip = { version = "9.5.1", default-features = false, features = ["deflate-flate2"] }`, `flate2 = { version = "1.1.10", default-features = false, features = ["rust_backend"] }` (feature `rust` в 1.1.x не существует), `serde_json = "1.0.154"` — уже транзитивен (rust-i18n), ноль churn. Base64-decoder руками (~25 строк), tar-читатель руками.

## Constraints

- В проекте нет HTTP/хеши/архивов/`self_replace` в manifests и `Cargo.lock` → approved набор (`self-replace`, `ureq`, `sha2`, `zip` + объявление `flate2`/`serde_json`) добавляется как новые депы; AGENTS.md требует confirmation для любого нового пакета. Lock-churn: ~22 новых пакетов (ureq/rustls/ring/http/sha2-chain/zip), ноль изменений версий существующих записей.
- `docs/spec.md` §5 (:612–613) запрещает сетевые запросы из процесса; §10 (:858–860) «без инсталлятора и автообновления» → amendment раздела обязателен до реализации.
- Бюджет (approved 2026-11-11, пересмотрен): **exe < 12 MB**, RAM < 30 MB, CPU < 1% idle (spec §5 :607–611 — §5 правится в Stage 8); `opt-level="z"`, `lto="thin"`, `strip=true`; депы feature-trimmed, итоговый размер замеряется release-сборкой. Замер: текущий windows-gnu exe 8.99 MB, прирост ≈ 1.76 MB (rustls+ring ≈ 1.46 MB — необратимая цена HTTPS без async/native OpenSSL) → проекция ~10.5–10.7 MB, старый лимит 10 MB превышался бы.
- `#![forbid(unsafe_code)]` в root crate: `unsafe` внутри сторонних крейтов допустим, в нашем коде — нет.
- Root package bin-only → тесты новой чистой логики только в sibling `update.tests.rs`, `update_notes.tests.rs`, `update_install.tests.rs`; `tests/unit/` импортировать крейт не может.
- Новые поля `General` требуют `Eq` + `#[serde(default)]` и дефолты в `general_with_home()`.
- Новые строки UI → `locales/app.yml` на всех 6 локалях; `i18n.tests.rs` пинит число ключей (:236/:355/:521) → assertions обновляются вместе с добавленными ключами: заголовок секции, метка дропдауна, кнопка принудительной проверки добавлены, а старый `general.update_check_label` снят как мёртвая формулировка (метку секции заменил `update.check_label`) → итог **94** (92 + 3 − 1), плюс тест на отсутствие снятого ключа; Stage 11 добавляет `update.no_updates_available` («Обновлений нет») → пин **95** (текст ошибки не локализуется — verbatim-английское сообщение `UpdateError`).
- Resident-контракты: tray `Exit` — единственный exit; `<config>.lock` + pid-probe (`tasklist`); pad pump не останавливается; один winit `EventLoop`; `App::logic` — единственная точка дренажа; no async runtime.
- `std::env::temp_dir()` раньше не использовался (`%TEMP%` — новая территория); рантайм-файлы сейчас лежат рядом с бинарником/в config dir.
- Формы metadata: `release.yaml` → `version`, `releaseDate` (quoted ISO-8601 ms + Z), short `commit_sha`, `files[] {url, type, sha512, size}`; `sha512` = base64 raw digest (88 символов); nightly tag — prerelease, ассеты заменяются in place, target commit двигается.
- Target mismatch: shipped Windows artifact — `x86_64-pc-windows-msvc`, локальные сборки — `-gnu`; суффикс `-dev` в dev-версиях.
- Gates: `./scripts/check.sh` (Linux), `./cargo.sh test --no-run --target x86_64-pc-windows-gnu` (Windows compile), `./scripts/check_full.sh` на границах stages; Windows hardware/runtime проверка — на Windows-хостах.

## Open questions

1. Поведение перезапуска в режиме, где новый процесс не может взять lock (например antivirus) — fallback: log + тост, старый процесс остаётся живым.
2. Формат имени временных файлов (`virshot-update-<sha>/…`) — фиксируется на этапе install.
