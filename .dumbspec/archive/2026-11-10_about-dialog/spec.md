## Approach

- **Метаданные сборки:** `build.rs` в корневом пакете; `shadow-rs` 2.0.0 как `[build-dependencies]` (`default-features = false, features = ["build"]`) и как runtime-dep (`default-features = false`, нужен только макрос). Реальный API (проверено, R3): `shadow_rs::ShadowBuilder::builder().build_pattern(BuildPattern::RealTime).build()` в `build.rs` + `shadow_rs::shadow!(build);` в crate — `set_metadata()` в 2.0.0 **не существует**. Генерируемые константы (проверено по `OUT_DIR/shadow.rs`): `PKG_VERSION`, `BUILD_TIME`/`BUILD_TIME_3339`/`BUILD_TIMESTAMP`, `BUILD_RUST_CHANNEL` (`"debug"`/`"release"` — константы `DEBUG` в 2.0.0 **нет**), `SHORT_COMMIT`/`COMMIT_HASH`, `BRANCH`, `TAG`, `RUST_VERSION`, `BUILD_TARGET`/`BUILD_OS`/`BUILD_TARGET_ARCH`, `CARGO_TREE`. `git2` не нужен и не добавляется: git-константы заполняются вызовом `git` CLI (`src/git.rs:125-167`), при отсутствии git остаются `""` — код читает их как значения (фоллбэк «unknown»), без паник. `CARGO_METADATA` не referenced (denied by default).
- **Дата сборки:** ISO-8601 со смещением Europe/Moscow `+03:00` (решение пользователя 2026-11-10). Штамп `shadow-rs` берёт **таймзону сборочной машины** (`jiff::Zoned::now()`), а GitHub-раннеры UTC ⇒ московское смещение считается нашим `build.rs` на `std` (фиксированный `+03:00`, DST в Москве нет с 2014) и эмбедится через `cargo:rustc-env=VIRSHOT_BUILD_TIME` — по образцу `hidpad-poc/build.rs:12-39`. Свежесть на каждую сборку обеспечивает `BuildPattern::RealTime` (дефолтный `Lazy` в debug не эмитит rerun-директивы и дата может протухнуть).
- **Markdown:** `egui_commonmark` 0.26.0 с `default-features = false` и **без дополнительных фич** (проверено, R4): `pulldown_cmark` — no-op флаг, парсинг работает потому что `pulldown-cmark` обязательный dep. Рендер: `CommonMarkViewer::new().show_scrollable(id, ui, &mut cache, &CommonMarkScrollOptions::default().viewport_cache(true), text)` (или `show()` внутри `egui::ScrollArea::vertical().auto_shrink([false, true])`); viewer `!Send` — создаётся внутри closure viewport-а, `CommonMarkCache` живёт в state приложения. В About рендерится **весь** `CHANGELOG.md` со скроллом.
- **Модуль `src/about.rs`:** один модуль = один файл (конвенция проекта). Ответственность: содержимое окна About (заголовок + ссылки + строка билда + changelog) и его отрисовка. `pub(crate)` по умолчанию.
- **Фон и отступы (v3, R7):** причина «просвечивания» — `App::clear_color` возвращает `egui::Color32::TRANSPARENT` (`src/gui.rs:2297-2299`) для **всех** viewport'ов, а egui не рисует фон дочернего окна. Правится внутри `about::paint`: `egui::CentralPanel` (его frame = `Frame::central_panel(style)` = `inner_margin(8).fill(style.visuals.panel_fill)` и разворачивается на весь rect окна — `frame.rs:191-193`, `panel.rs:1411-1415`) с переопределённым frame: `CentralPanel::default().frame(Frame::central_panel(&ui.style()).inner_margin(egui::Margin::symmetric(16, 8)))`. `clear_color` **не** меняется — прозрачность нужна toast/overlay-чипам. `Frame::show` вместо CentralPanel не годится: он красит только min-rect контента (`frame.rs:509-510`), низ окна остался бы прозрачным.
- **Заголовок (v3):** `ui.horizontal(|ui| …)` — иконка + `egui::RichText::new(…).size(22.0).strong()`. Синтетического bold в egui нет: `strong()` = более сильный цвет (`style.rs:1257-1259`), вариационный `wght` недоказан (фонт статический) ⇒ «красивее» = размер + strong-цвет + иконка, не начертание. Иконка без loaders (`egui_extras` с `default-features = false` ⇒ `ImageSource::Uri/Bytes` ничего не рисуют): `icons::rgba(icons::APP_ICON_PNG)` → `egui::ColorImage::from_rgba_unmultiplied` → `ctx.load_texture` → `ui.image((texture.id(), texture.size_vec2()))`; `TextureHandle::drop` освобождает id (`texture_handle.rs:25-29`), поэтому текстуру владеет `SettingsApp` (загружается при открытии About, в closure передаётся `Arc<TextureHandle>`), а не создаётся каждый pass. Заголовок печатается новым ключом каталога (`ViRShot %{version}` — каталог сейчас использует строчное `virshot`).
- **Ссылки (v3):** `ui.hyperlink_to(label, url)` ⇒ `OutputCommand::OpenUrl` ⇒ egui-winit открывает системный браузер (`egui-winit-0.37.0/src/lib.rs:1250-1252`, `webbrowser::open` спавнит `xdg-open`/реестровый обработчик) — наш процесс не делает HTTP, поэтому `docs/spec.md:574` «никаких сетевых запросов» не нарушается; §4.6 («Ссылок/сетевых запросов нет», `docs/spec.md:563`) правится. URL `https://github.com/Apkawa/virshot` authoring-константа в коде: в манифестах `repository` нет, литерал owner/repo в трекаемых файлах отсутствует, источник — `git remote` (R7). Клик требует eframe-фичи `links` (`eframe/Cargo.toml:85` → `egui-winit/links` → `webbrowser`); без неё клик только логирует warn.
- **Строка билда (v5):** под ссылками одна строка `<short sha> <date>` из `build::SHORT_COMMIT` + `build_date()` (пустые значения → `unknown`); маркер `debug|release` убран по решению пользователя 2026-11-11 вместе с ключами `about.marker_debug`/`about.marker_release` (каталог 84 → 82 ключей). `metadata_lines()` (версия/сборка/коммит/ветка) не показывается: версия уже в заголовке, ветка — не по решению пользователя.
- **Версия и `-dev` (v5, проверено R12):** детекция через уже генерируемую `build::TAG` — shadow-rs берёт её из `git tag -l --contains HEAD` (`git.rs:580-582`, пустая строка если тегов нет) и в CI заполняет из `GITHUB_REF=refs/tags/<t>` при `GITHUB_ACTIONS=true` (`git.rs:349-390`). Правило: `build::TAG == concat!("v", build::PKG_VERSION)` → чистая `<версия>`, иначе `<версия>-dev` (пустой TAG, локальная сборка, `nightly`). Новый dep не нужен, `unsafe` не нужен, `build.rs` не меняется; `BuildPattern::RealTime` пересобирает build-скрипт каждую сборку, поэтому новый тег подхватывается следующей сборкой. Суффикс формируется чистой функцией в `src/about.rs` и применяется в `version_from_build()` (контракт `virshot <ver> (<sha>) built <ISO +03:00>` — меняется только `<ver>`) и в заголовке `app_title(...)`; e2e-assert `tests/e2e/cli_headless.rs:65-98` проверяет наличие `env!("CARGO_PKG_VERSION")`, суффикс его не ломает.
- **Окно:** child viewport основного eframe-цикла через `ctx.show_viewport_deferred` (декорированное, обычное окно), регистрируемый **каждый** logic-pass пока окно живое (незарегистрированный pass закрывает viewport — `crates/overlay/src/host.rs:325-327`). `OverlayHost` не подходит: его chrome захардкожен как чип (`decorations(false)`, `always_on_top`, `taskbar(false)`) и `Painter` не рисует фон.
- **Кнопки окна (v4, проверено R9):** builder About остаётся **константным** для id `virshot-about` и получает `with_minimize_button(false)` + `with_maximize_button(false)` при сохранённых `with_decorations(true)` и `with_resizable(true)`: на Windows это снимает `WS_MINIMIZEBOX`/`WS_MAXIMIZEBOX`, оставляя `WS_CAPTION` + `WS_SIZEBOX` ⇒ заголовок, крестик и ресайз за границы живы. `with_decorations(false)` **не** используется — он убирает и title bar, и рамку ресайза (`WS_CAPTION|WS_SIZEBOX` срезаются, `window_state.rs:433-436`). Runtime-команда `ViewportCommand::EnableButtons` не нужна: chrome задаётся на создании, а изменение флагов в `patch()` пересоздавало бы OS-окно (`viewport.rs:886/891/896`). Ограничение: winit 0.30.13 реализует `set_enabled_buttons` только на Windows/macOS — на X11/Wayland кнопки не убираются (no-op, `x11/window.rs:1443`, `wayland/window/mod.rs:399-407`); целевая платформа — Windows.
- **Закрытие (v4, проверено R10):** текущий reading закрытия в root-pass (`raw.viewports…close_requested()`) физически не может сработать: событие `Close` кладётся в info **дочернего** viewport'а (`glow_integration.rs:1075`), child-pass выполняется раньше root-pass (`run.rs:147-152`), `ViewportInfo::take()` выносит события (`viewport_info.rs:118-123`) и eframe очищает info child'а после его pass'а (`glow_integration.rs:853`) — root-pass читает уже очищенные infos (`glow_integration.rs:699-703`). Механика как в `crates/overlay/src/host.rs:494-501`: закрытие наблюдает **child-pass** через разделяемый флаг; следующий root-pass снимает `about_open` и **не** вызывает `show_viewport_deferred` ⇒ egui GC убирает viewport из `viewport_output`, `remove_viewports_not_in` роняет `Arc<Window>` и winit уничтожает окно. `ViewportCommand::Close` к child — только флаг (окно сам не гасит), `CancelClose` для child игнорируется, `Visible(false)` даёт скрытый фантом вместо закрытого окна. Повторный пункт меню трея **не** закрывает окно (решение пользователя 2026-11-11): он поднимает уже открытое окно — `ctx.send_viewport_cmd_to(id, ViewportCommand::Focus)`; закрытие — только крестик OS-окна (плюс shutdown по `Exit`). Повторное открытие позже работает с тем же id после GC.
- **Открытие из трея:** 4-й `MenuId` (`virshot-about`) + `TrayAction::About`, обрабатывается в `gui::logic` по тому же образцу, что `ShowSettings` (`src/gui.rs:2136-2139`): `request_repaint()` при открытии (child стартует `Visible(false)` и показывается после первой отрисовки).
- **Локализация:** новый ключ `tray.about` + ключи текста About; тест полноты каталога требует все 6 локалей на каждый ключ (`src/i18n.tests.rs:344`).
- **GUI-less fallback:** в `park_without_gui` (`src/main.rs:460-486`) `About` деградирует в WARN, как `ShowSettings`.
- **CLI:** `virshot --version` печатает `virshot <версия> (<short sha>) built <ISO-8601 +03:00>` (решение Stage 1: формат сохраняет e2e-контейнермент `virshot` + версия). Текущий clap-контракт `#[command(version, ...)]` (`src/main.rs:131-132`) заменяется на явный вывод; e2e-тест `tests/e2e/cli_headless.rs:65-76` обновляется, `docs/spec.md` §8 пополняется.
- **Тесты:** root-пакет bin-only ⇒ unit-тесты в sibling `src/about.tests.rs` (чистая логика: форматирование строки версии, форматирование строки билда, чтение встроенного changelog; на v3 вместо тестов `metadata_lines` — тесты строки билда и заголовка). Тесты трея пинят 4 id/labels включая `virshot-about` (сделано на Stage 3).
- **Docs (v3):** `docs/spec.md` §4.6 правится — ссылка на GitHub становится in-scope («Ссылок/сетевых запросов нет», `docs/spec.md:563` → «ссылки открываются системным браузером; приложение само не делает сетевых запросов»), §5 «Безопасность» (`:574`) уточняется той же формулировкой.

## Constraints

- Стек зафиксирован: `eframe 0.37.0` (`default-features=false, features=["glow","default_fonts","x11","wayland","links"]` — `links` добавлена на v3 по подтверждению пользователя), `egui 0.37.0`, winit 0.30.13, `tray-icon 0.26.1 (ksni)`, `muda 0.21.2`. Multi-viewport в egui 0.37 не gated фичей — `show_viewport_deferred` доступен без изменений фич; child viewport на desktop = реальное OS окно (toast-чипы это уже доказывают на текущем feature set).
- `links` тянет единственный новый crates.io пакет — `webbrowser 1.2.6` (сегодня отсутствует в `Cargo.lock`, R7): чистый Rust, спавнит `xdg-open`/реестровый обработчик через `std::process::Command`; совместимость с Windows-gnu cross-build проверяется гейтом `./cargo.sh test --no-run --target x86_64-pc-windows-gnu`.
- Факты egui 0.37 для вёрстки (R7): цвета — поля `Visuals::panel_fill`/`window_fill` (методов `*_bg_color()` нет), `hyperlink_color`; `egui::Margin` целочисленный (i8, `From<f32>` округляет) ⇒ отступы задаются `Margin::symmetric(16, 8)`; `egui::TextureImage` в 0.37 нет — тип `egui::ImageData` (`From<ColorImage>`); loaders выключены, путь только через текстуру; `Frame` красит min-rect контента, `CentralPanel` — весь rect.
- `egui_commonmark 0.26.0` требует `egui ^0.37.0` — совместим с залокированным egui (0.37.0), version churn нулевой. С `default-features = false` в lock добавляются только `egui_commonmark_backend` 0.26.0, `egui_extras` 0.37.0 (все image/file/http/svg loaders выключены) и `pulldown-cmark` 0.13.6 (+ `bitflags`, `unicase`, `memchr`). Default-фичи вместо этого тянули бы `image`/`mime_guess2` и `fancy-regex` (флаг `regex` — это **fancy-regex**, не crate `regex`).
- `shadow-rs 2.0.0`: обязательный dep `const_format ^0.2.22`; `build = ["dep:jiff","is_debug/std","std"]`, `default = ["git2","build"]`. С `features = ["build"]` транзитивные dep чистые Rust (`const_format`+proc-macro, `is_debug`, `jiff`+`jiff-core`/`jiff-static`); `git2`/`libgit2-sys` (C-билд на всех целях, включая Windows cross-build из Linux), `cargo_metadata`, `serde_json` не добавляются. `git2` в локальном кэше — 0.21.0, не удовлетворяет `^0.20.0`, но он и не нужен. MSRV crate не объявлен (edition 2021), rustc 1.99.1 подходит; `unsafe` в crate только в `#[cfg(test)]` ⇒ root `#![forbid(unsafe_code)]` не нарушается; bin-only пакет поддерживается.
- Sandbox онлайн: sparse index и `static.crates.io` отвечают 200 (проверено), `./cargo.sh` (`CARGO_HOME=./.cache/cargo`) — единственный способ гонять cargo здесь.
- `#![forbid(unsafe_code)]` в root (`src/main.rs:63`) — новый модуль не добавляет `unsafe`.
- Размерный бюджет `< 10 МБ` (`docs/spec.md:551`) уже превышен локальным Linux GNU release-артефактом (15.1 МБ) ещё до этой задачи; после реализации измерено 15,716,256 байт (Δ +591,392 байт, R6) — превышение остаётся свойством текущего release-профиля, решение по фичам (`default-features = false`) удержало delta минимальной.
- Blast radius трея (проверено): `src/tray.rs:36-43,74-76,87-89,98-117,143-150`, исчерпывающие матчи в `src/gui.rs:2136,2140,2151` и `src/main.rs:465,469,478`, тесты id `src/tray.tests.rs:184-192`, локали `locales/app.yml:532-554`.
- `include_str!` резолвится относительно файла-модуля (`src/main.rs:78`, `crates/icons/src/lib.rs:16`) ⇒ `include_str!("../CHANGELOG.md")` из `src/about.rs`.
- Content changelog меняется по релитному потоку: без tag — `## [unreleased]`, после bump — `## [x.y.z] - дата`; nightly и tagged бинарники встраивают разные тексты.
- Версионный источник остаётся `Cargo.toml` (ZeroVer, `cliff.toml [bump]`, `scripts/release.sh`); сборочный штамп — второй, независимый источник той же версии/sha/date. `release.sh` коммитит/tag **до** CI, поэтому sha локально собранного бинарника может отличаться от packaged.
- Конвенции: `./scripts/check.sh` после каждой партии правок, `./scripts/check_full.sh` перед коммитом; коммиты Conventional Commits; временные файлы в `./.tmp/`, кэши в `./.cache/`.

## Открытые вопросы

Решения пользователя (2026-11-10): `shadow-rs` без `git2` (sha эмбедится на сборке, без libgit2), дата ISO-8601 в московском смещении `+03:00`, `egui_commonmark` с обрезанными фичами, весь CHANGELOG со скроллом, `--version` расширен.

Технические неизвестные закрыты на Stage 1 плана (проверено, R3/R4):
1. Имена констант `shadow-rs` 2.0.0 и поведение фичи `build` без `git2` — закрыто (R3): `set_metadata()` не существует, API = `ShadowBuilder::builder().build()` + `shadow!(build)`; константы `PKG_VERSION`, `BUILD_TIME_3339`, `SHORT_COMMIT` и т.д.; git-данные приходят из `git` CLI без `git2`.

3. Свежесть даты — закрыто (R3): `BuildPattern::RealTime` эмитит rerun-директивы; московское смещение считаем сами в `build.rs`.
4. Формат `virshot --version` — решён: `virshot <версия> (<short sha>) built <ISO-8601 +03:00>`.

Закрыто реализацией на Stage 3 (проверено, R6):
5. Поведение закрытия About при tray `Exit` — закрыто: `Exit` закрывает root viewport, eframe гасит дочерние viewport'ы на shutdown (`save_and_destroy`, `run.rs:170-174`); child не блокирует выход. Закрытие крестиком оказалось **не** исправлено тем reading'ом (см. вопрос 9, R10) — оно чинится в v4.

Решения пользователя на v3 (2026-11-10): ссылки открываются через eframe-фичу `links` (новый dep `webbrowser` подтверждён выбором варианта); строка билда под ссылками = `<short sha> <date> · <debug|release>`; «Ветка» и строка «Создана …» не показываются; форма заголовка = иконка + крупный `ViRShot <версия>`.

Остались две детали, проверяемые реализацией и гейтами (R7, unverified):
6. Поведение OS-окна после непрозрачного fill: причина прозрачности доказана (alpha-0 clear + отсутствие fill), но композитинг (Wayland/X11/Win32) после непрозрачной панели не runtime-тестирован — проверяется на display и на Windows acceptance.
7. `webbrowser` на Windows-gnu cross-build: компиляция проверяется гейтом `./cargo.sh test --no-run --target x86_64-pc-windows-gnu`, фактическое открытие ссылки — на Windows-машине.

Технические неизвестные v4 закрыты research-этапом (проверено, R9/R10):
8. Как убрать кнопки «свернуть»/«развернуть» у дочернего viewport'а сохранив ресайз — закрыто (R9): `ViewportBuilder::with_minimize_button(false)`/`with_maximize_button(false)` на builder'е child'а (`viewport.rs:586/593`) → winit `WindowAttributes::with_enabled_buttons` на создании окна; `with_decorations(false)` не годится (гасит и title bar, и рамку ресайза); отдельных `with_minimizable`/`with_maximizable` в egui 0.37 нет; безопасного handle к winit-окну child'а нет (`Frame::winit_window()` возвращает root), поэтому raw-Win32 не используется (`unsafe` запрещён).
9. Почему окно About не закрывается — закрыто (R10): событие `Close` consumes child-pass раньше root-pass, поэтому root-reading `close_requested()` всегда `false`; само OS-окно winit не уничтожает (уничтожение только при drop `Arc<Window>`, которого не происходит пока viewport перерегистрируется). Правка — наблюдение закрытия в child-pass + прекращение регистрации в следующем root-pass (образец `crates/overlay/src/host.rs:494-501`), toggle из трея.

Остались проверки на железе (v4):
10. Фактическое disappearance окна по крестику на Windows — проверяется на Windows-машине. На этом хосте закрытие проверено headless под openbox (Xvfb): крестик title-bar даёт `WindowEvent::CloseRequested for viewport Some("F99B")`, окно уничтожается, приложение остаётся в трее, повторный пункт открывает новое окно. Без WM закрыть нельзя: winit 0.30.13 не выбирает `EventMask::CLIENT_MESSAGE` (`x11/window.rs:261-272`), а `xdotool 3.2` не имеет `windowsend` (`windowkill` убивает клиент).
11. Видимость кнопок «свернуть»/«развернуть» — проверяется только на Windows/macOS: X11 и Wayland в winit 0.30.13 документально игнорируют `set_enabled_buttons`, и openbox рисует свои кнопки независимо от флагов приложения.
12. Детекция `-dev` в CI: fallback shadow-rs по `GITHUB_REF` и shallow-checkout без тегов в build- job проверены чтением источника shadow-rs и локальной симуацией (`GITHUB_ACTIONS=true GITHUB_REF=refs/tags/v0.1.0 ./cargo.sh build` → `TAG="v0.1.0"`), но не реальным прогоном GitHub Actions — подтверждается первым релизом с тегом `v<version>` (на remote сейчас только `nightly`).
