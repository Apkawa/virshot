Toast chips prove this works on the current feature set.

**Gaps / risks for About**
1. Adding a 4th menu item touches: `MENU_ID_*` consts, `build_menu`, `menu_labels()` (3-tuple), `action_for_menu_id`, `TrayAction` (closed enum), exhaustive matches in `gui::logic` (`src/gui.rs:2135-2156`) and `park_without_gui` (`src/main.rs:464-481`), `tray.tests.rs:187-189` (asserts exactly 3 ids), and new locale keys in `locales/app.yml`.
2. `OverlayHost` cannot host a decorated dialog (chrome hardcoded, `Painter` paints no background). A normal About window needs its own `ctx.show_viewport_deferred` registration in the app loop, re-registered every pass while alive.
3. No second `run_native` / EventLoop is possible (single-loop rule).
4. About can be opened while settings is hidden (children painted from `logic`); needs `request_repaint()` on open since children start `Visible(false)` and show after first paint.
5. Exit: root-only `Close`; a still-open child viewport must not block shutdown and must not be re-registered once closed (`host.rs:314-323` precedent).
6. GUI-less fallback (`park_without_gui`) has no eframe context — About must degrade to a WARN like `ShowSettings` (`src/main.rs:478-480`).
7. Idiomatic extension shape: new `MenuId` + `TrayAction::About` drained in `poll()` and handled in `gui::logic`, mirroring ShowSettings/TakeScreenshot.

## R3 — shadow-rs 2.0.0 real API (verified from docs.rs + GitHub tag v2.0.0 sources)

- **`shadow_rs::set_metadata()` does not exist in 2.0.0.** Real API: `shadow_rs::ShadowBuilder::builder().build()` called from `build.rs` (as `[build-dependencies]`) + `shadow_rs::shadow!(build);` in the crate (`src/lib.rs:195-196` re-export under `cfg(feature = "build")`, macro at `:216-224` → `include!(concat!(env!("OUT_DIR"), "/shadow.rs"))`).

- **Feature gating:** `build = ["dep:jiff","is_debug/std","std"]`, `default = ["git2","build"]`. With `default-features = false` and no `build` feature nothing is generated — `shadow!(build)` fails at compile time (`couldn't read OUT_DIR/shadow.rs`). Minimal build-dependency feature set: `features = ["build"]`.
- **git2 is NOT required for git data**: git constants are collected by shelling to the `git` CLI (`src/git.rs:125-167 init_git()` — `git log --pretty=format:"%h"`, `git rev-parse HEAD`, `git describe --tags`); the `git2` feature only adds a libgit2 fallback (`init_git2` is `#[cfg(feature = "git2")]`). Missing git ⇒ constants stay `""`, still compiles. ⇒ `SHORT_COMMIT`/`COMMIT_HASH` come from shadow-rs itself with `build` only, no C build, no libgit2-sys.
- **Timestamps:** `jiff::Zoned::now()` ⇒ build-host **local** timezone. `BUILD_TIME_3339` = RFC 3339 **with offset when host tz is non-UTC** (`2026-11-10T16:08:08+03:00` on a Moscow host; `...Z` on UTC runners). `BUILD_TIME` = `%Y-%m-%d %H:%M:%S %:z`. `SOURCE_DATE_EPOCH` forces UTC. ⇒ Moscow `+03:00` is **not** guaranteed on GitHub runners (UTC); must be computed in `build.rs` ourselves.
- **Freshness:** `BuildPattern::Lazy` (default) emits **no rerun directives in debug** ⇒ stale timestamps possible; release behaves like `RealTime` (`cargo:rerun-if-changed=OUT_DIR`, `cargo:rerun-if-env-changed=SOURCE_DATE_EPOCH`, plus per-const `rerun-if-env-changed`). Force `.build_pattern(BuildPattern::RealTime)` for always-fresh timestamps (src/build.rs `rerun_if`).
- **Custom values:** no metadata map API; custom constants go through the `HookExt` hook (`ShadowBuilder::builder().hook(h)` appends extra `pub const` lines to OUT_DIR/shadow.rs — example `example_shadow_hook/build.rs`). Equivalent simpler shape: `cargo:rustc-env=VIRSHOT_BUILD_TIME=<...>` + `env!("VIRSHOT_BUILD_TIME")`, matching the repo's `hidpad-poc/build.rs` precedent.
- **MSRV / safety / shape:** no `rust-version` declared (edition 2021 crate); rustc 1.99.1 fine; no `unsafe` needed from consumer code (crate's only `unsafe` is inside `#[cfg(test)]`); works in bin-only packages ("binary, lib, cdylib, dylib"); cargo auto-detects root `build.rs`.
- **Transitive deps with `features = ["build"]`:** shadow-rs + `const_format` (+ `const_format_proc_macros`) + `is_debug` + `jiff` (+ `jiff-core`, `jiff-static`, proc-macro2/quote/syn) — all pure Rust, no native build. `git2`/`libgit2-sys`/`cargo_metadata`/`serde_json`/`document-features` are NOT pulled. Build-dependencies resolve separately from runtime deps, so runtime `shadow-rs` with `default-features = false` compiles without jiff.
- **CI note:** `release.yml` package job uses `fetch-depth: 0`; build jobs do not, so `TAG`/`LAST_TAG`/`COMMITS_SINCE_TAG` degrade to empty/0 there (compiles fine).

- **How shadow-rs 2.0.0 fills tag fields** (vendored `.cache/cargo/registry/src/index.crates.io-1949cf8c6b5b557f/shadow-rs-2.0.0/src/`): `TAG` ← `git tag -l --contains HEAD` (`git.rs:580-582`) — lists tags whose tagged commit *contains* HEAD ⇒ in practice the tag(s) pointing exactly at HEAD; empty string when no tag (executor `git.rs:552-564` trims stdout, git failure → `Some("")` → `""`); multiple tags at HEAD would yield a multiline value. `LAST_TAG`/`COMMITS_SINCE_TAG` ← `git describe --tags --abbrev=0 HEAD` + `git describe --tags HEAD` parsed by `parse_git_describe` (`git.rs:586-607`, `:609-653`): the `-N-g<sha>` suffix is **stripped** — `LAST_TAG` is the bare tag name, `COMMITS_SINCE_TAG` is `N` (0 exactly at the tag). No `git2` feature needed; `git` CLI subprocess only.

- **Release tagging reality:** `release.yml` triggers on `push tags:['v*']` + `push master` + `workflow_dispatch` (:4-7); kind/tag resolution (:76-85): `ref_type=tag` → `kind=release`, tag=`github.ref_name` (`v<version>`), else `kind=nightly`, tag=`nightly`; version read from `Cargo.toml` (:86-90); package job checks out with `fetch-depth: 0` (:65-67); publishing via `gh release create/edit --target <sha>` (:111-135). `scripts/release.sh` (:73-85) bumps Cargo.toml to the bare version and creates annotated tag `v<version>` — so on a tag-triggered CI build `TAG == "v" + PKG_VERSION` holds. A plain `git tag --points-at HEAD` in `build.rs` **works locally** (exit 0, empty output when untagged) but in the CI **build job** it would see nothing (shallow checkout, no tags) — the shadow-rs `GITHUB_REF` fallback is what makes tag detection reliable in CI.

Alternative if `TAG` multiline/exactness ever matters: `build.rs` can emit `cargo:rustc-env=VIRSHOT_TAG=$(git tag --points-at HEAD | head -1)` with a `GITHUB_REF` env fallback — same subprocess, no dependency.
