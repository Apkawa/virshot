use hidapi::{HidApi, HidDevice};
use std::time::Duration;

const XBOX_VENDOR_ID: u16 = 0x045e;
// Product ID может отличаться (0x0b12 для Series X|S, 0x02ea для Xbox One и т.д.)
const XBOX_PRODUCT_ID: u16 = 0x0b12; 

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let api = HidApi::new()?;

    let device = api.open(XBOX_VENDOR_ID, XBOX_PRODUCT_ID)?;

    let mut buf = [0u8; 64]; // Буфер для чтения отчёта

        match device.read(&mut buf) {

                let share_byte_index = if size < 48 {
                    18 // Для прошивок 5.0 и 5.1
                } else {
                    22 // Для прошивки 5.5 и новее
                };

                // Проверка, что индекс не выходит за пределы прочитанных данных
                if share_byte_index < size {

                    if is_share_pressed {

В отличие от Vendor ID и Product ID, которые просто идентифицируют конкретную модель, **Usage Page** и **Usage** — это стандартизированные поля, которые сам производитель закладывает в HID-дескриптор устройства, чтобы сообщить системе, к какому классу оно относится.

### 🎯 Ключевые поля для идентификации: Usage Page и Usage

Каждое HID-устройство при подключении сообщает Windows (и `hidapi`) свои "Usage Page" и "Usage". Именно эта пара значений является основным способом понять, что перед вами: клавиатура, мышь или игровой контроллер.

Для игровых устройств используется **Usage Page `0x01` (Generic Desktop Controls)**. Внутри этой страницы конкретный тип устройства определяется полем **Usage ID**:

*   **`0x04` — Joystick**: Простой джойстик с осями и, возможно, небольшим числом кнопок.
*   **`0x05` — Game Pad**: Полноценный игровой контроллер (геймпад), как ваш Xbox. Это наиболее вероятное значение для современных контроллеров.
*   **`0x08` — Multi-axis Controller**: Устройство с множеством осей, например, для 3D-навигации или сложных симуляторов.

Таким образом, если вы видите, что устройство имеет **Usage Page = `0x01`** и **Usage = `0x04`** или **`0x05`**, вы можете с высокой уверенностью считать его игровым контроллером.

### 💻 Как это получить в Rust через `hidapi`

Крейт `hidapi` предоставляет удобный и безопасный доступ к этой информации. При перечислении устройств через `api.device_list()` каждый элемент `DeviceInfo` содержит методы для получения этих полей.

Однако есть важный нюанс: **на Linux при использовании бэкенда `libusb` методы `usage()` и `usage_page()` могут быть недоступны** (они возвращают 0 или не работают). На Windows такой проблемы нет, так как используется нативный бэкенд, который эти данные предоставляет.

Вот пример безопасного кода на Rust, который фильтрует устройства и находит игровые контроллеры:

```rust
use hidapi::HidApi;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let api = HidApi::new()?;

    println!("Поиск игровых контроллеров...");

    for device in api.device_list() {
        // Получаем Usage Page и Usage. На Windows они должны быть заполнены.
        let usage_page = device.usage_page();
        let usage = device.usage();

        // Проверяем, что это Generic Desktop (0x01) и один из игровых Usage ID
        if usage_page == 0x01 && (usage == 0x04 || usage == 0x05) {
            let product_name = device.product_string().unwrap_or("Неизвестное устройство");
            let vid = device.vendor_id();
            let pid = device.product_id();

            println!(
                "Найден контроллер: {} (VID: {:04x}, PID: {:04x}, Usage Page: {:02x}, Usage: {:02x})",
                product_name, vid, pid, usage_page, usage
            );
            
            // Здесь можно открыть устройство: api.open(vid, pid)?
        }
    }
    Ok(())
}
```

### 🔍 Дополнительные уровни идентификации

Хотя пары Usage Page/Usage обычно достаточно, для особых случаев можно использовать и другие данные:

*   **Vendor ID и Product ID (`vid`/`pid`)**: Уникальны для каждого производителя и модели. Это самый точный способ, но он не даёт понять *тип* устройства, а только его конкретную модель. Например, `VID 0x045e` — это Microsoft, а `PID` укажет на конкретную ревизию контроллера.
*   **Строковые дескрипторы**: Поля `manufacturer_string` и `product_string` содержат текстовое описание, которое можно использовать для отображения пользователю или как дополнительный фильтр.
*   **HID Report Descriptor**: Это самый низкоуровневый и мощный инструмент. Дескриптор — это байтовый массив, который полностью описывает структуру данных, отправляемых устройством. Проанализировав его, можно определить не только тип, но и точное количество кнопок, осей и их разрешение. Однако его парсинг — это сложная задача, которая вряд ли понадобится, если только вы не столкнулись с очень нестандартным устройством.

### 💎 Итог

Да, по HID можно надёжно вычислить тип устройства. Наиболее практичный путь в рамках вашего проекта на Rust — это использование крейта `hidapi` для проверки пары **Usage Page (`0x01`)** и **Usage (`0x04`/`0x05`)**. Это безопасный, стандартизированный и достаточно гибкий метод, который позволит вам отличать игровые контроллеры от других HID-устройств, не полагаясь на хрупкие списки VID/PID.
