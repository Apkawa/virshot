# Спецификация проекта: VibeShot

## 1. Обзор проекта

**VibeShot** — это ультралегковесная утилита для создания скриншотов на Windows (с потенциалом кроссплатформенности), и позволяет делать скриншоты при помощи геймпада. Основная цель — заменить тяжелые комбайны вроде ShareX и ненадежные ремапперы, предоставив стабильный, безопасный и незаметный инструмент .

## 2. Цели и ограничения (Scope)

**Входит в MVP (Минимально жизнеспособный продукт):**

- Прямое чтение сигналов геймпада (без эмуляции клавиатуры).
- Захват экрана (скриншот).
- Визуальное подтверждение (оверлей-уведомление) без сворачивания игры.
- Окно настроек (выбор папки, формата, кнопки геймпада).
- Работа в системном трее (сворачивание, контекстное меню).
- Сохранение конфигурации в локальный файл.
- пользовательский шаблон пути файла который включает в себя.
  * dt `%y`,`%mo`,`%d` и тд, в том числе iso dt (проработаем детальнее)
  * `%t` - заголовок активного окна (только для скриншотов окна)
  * `%n` - счетчик
  * `%ext` - расширение файла
  

**Не входит в MVP (На будущее):**

- Запись видео / Replay Buffer.
- Встроенный редактор изображений (обрезка, рисование).
- Поддержка эксклюзивного полного экрана (фокус на Borderless Windowed).


## 3. Технический стек

- **Язык:** Rust (latest stable, 2026-10-15, rust version 1.99.1).
- **UI и Оверлей:** `eframe` / `egui` (мульти-вьюпортная поддержка для окна настроек и оверлея).
- **Геймпад:** `gilrs` (XInput / DirectInput).
- **Захват экрана:** `xcap`.
- **Системный трей:** `tray-icon`.
- **Конфигурация:** `serde` + `toml` (человекочитаемый конфиг).
- **Логирование:** `tracing` + `tracing-subscriber` (для отладки без паник).
- **CLI:** `clap`

Разработка и тестирование ведется в wsl, т.е. требуется поддержка кроссплатформенности, проверка в windows будет проводиться вручную

## 4. Функциональные требования

### 4.1. Модуль ввода (Геймпад)

- Фоновый поток постоянно опрашивает подключенные геймпады через `gilrs`.
- Поддерживается "горячее" подключение (plug and play).
- В настройках пользователь может назначить любую кнопку (или комбинацию) на действие "Скриншот".
- _Защита от сбоев:_ Если геймпад отключился, поток не падает, а ждет переподключения.

### 4.2. Модуль захвата экрана

- Захват активного монитора (или монитора, где запущена игра).
- Форматы сохранения: `.png` (по умолчанию, без потерь), `.jpg` (с настройкой качества), `.webp`.
- Шаблон имени файла: `Screenshot_YYYY-MM-DD_HH-mm-ss.png`. (задается в настройках)
- Сохранение происходит в отдельном потоке, чтобы не вызывать микро-фризы в игре.

### 4.3. Оверлей-уведомление

- Отдельное прозрачное окно (`ViewportBuilder::default().with_transparent(true).with_always_on_top().with_decorations(false)`).
- Свойство `mouse_passthrough = true` (клики проходят сквозь оверлей в игру).
- Появление в углу экрана (позиция настраивается: правый нижний, левый верхний и т.д.).
- Анимация: плавное появление (Fade in) -> удержание 2 секунды -> плавное исчезновение (Fade out).
- предусмотреть показ на активном экране (или на всех экранах), например при игре на проекторе я не увижу уведомления скриншота.

### 4.4. Окно настроек (GUI)

- Обычное окно с рамкой.
1) **Вкладка "Основные":** 
  - Корневой путь сохранения (с кнопкой "Обзор"), например `E:\Screenshoots`
  - Шаблон имени файла: пример `FullScreen\%y-%mo\%y-%mo-%d\%iso.%ext` 
  - Шаблон имени файла для окна:`%t\%y-%mo\%y-%mo-%d\%t-%iso.%ext` 
  - формат файла, качество (если JPEG).
2) **Вкладка "Горячие клавиши":** 
  - Захват области: Ctrl+PrintScreen
  - Захват всего экрана: PrintScreen 
  - Захват активного окна: Alt+PrintScreen

  Для каждой из клавиши можно задать опциональную дополнительную клавишу, которая в том числе включает в себя клавиши геймпада (основная наша фича)
  т.е. 3 колонки, Тип клавиши, Основная, Дополнительная
  
3) **Вкладка "Оверлей":** 
  - Включение/выключение
  - выбор угла экрана
  - длительность показа.

### 4.5. Системный трей

- Иконка в трее.
- Левый клик — открыть окно настроек.
- Правый клик — контекстное меню: `Сделать скриншот`, `Настройки`, `Выход`.
- При закрытии окна настроек (крестиком) программа не завершается, а прячется в трей.

## 5. Нефункциональные требования

- **Размер бинарника:** < 10 МБ (в релизной сборке с `strip`, `lto`, `opt-level="z"`).
- **Потребление RAM:** < 30 МБ в фоновом режиме (без учета захвата).
- **Потребление CPU:** < 1% при простое.
- **Безопасность:** Никаких сетевых запросов. Полная приватность.
- **Отказоустойчивость:** Любая ошибка (нет доступа к папке, геймпад отвалился) должна логироваться и выводиться в UI/в лог файла, но не должна приводить к аварийному завершению программы.

## 6. Архитектура и потоки (Threading)

Чтобы программа не зависала, используется многопоточная модель:

1.  **Main Thread (UI):** Крутит цикл `eframe` (настройки + оверлей).
2.  **Input Thread (Gamepad):** Крутит цикл `gilrs`. При нажатии кнопки отправляет команду через канал `std::sync::mpsc` в главный поток.
3.  **Capture Thread:** Принимает команду, делает снимок экрана, сохраняет файл на диск.
4.  **Overlay Thread:** Управляет состоянием оверлея (показ/скрытие) по таймеру.
