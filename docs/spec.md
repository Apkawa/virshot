## 1. Обзор проекта

**VIRShot** — ультралегковесная утилита для создания скриншотов на Windows
(кроссплатформенная сборка: Windows + Linux), позволяющая делать скриншоты
по глобальному клавиатурному хоткею или кнопке геймпада (геймпад — только
Windows; Linux вне scope, §9). Основная цель — заменить тяжелые комбайны вроде ShareX и
ненадежные ремапперы: стабильный, безопасный и незаметный инструмент.

## 2. Цели и ограничения (Scope)

**Входит в MVP:**

- Глобальные клавиатурные хоткеи (system-wide hook): действие по клавиатурной
  комбо; работает, когда фокус у игры. Связываемый набор клавиш — широкий
  (`PrintScreen`, `ScrollLock`, `A`–`Z`, `0`–`9`, `F1`–`F24`, стрелки,
  навигационные (`Insert`/`Delete`/`Home`/`End`/`PageUp`/`PageDown`),
  `Space`/`Enter`/`Tab`, клавиши с физическим кодом, мультимедийные/дополнительные
  клавиши — §4.4); `Escape` и `Backspace` зарезервированы для capture-UI и
  отвергаются парсером конфига (`bindings::Error::ReservedKey`), модификаторы как
  основная клавиша — тоже. `ScrollLock` связываемый с v7: в UI он в
  `SUPPORTED_KEY_NAMES`, в конфиге — нотация `ScrollLock`, `bindings::parse_key`
  её принимает (round-trip строки «capture → конфиг → регистрация»). `CapsLock`
  и `NumLock` остаются исключены — они переключают системное состояние, а не
  дают нажатие для бинда.
- Геймпад-триггер (Windows, реализовано 2026-11-04): отдельный поток-помпа
  `gameinput.dll` (crate `crates/gamepad`, §3) — действие по кнопке геймпада из
  поля `pad`; вместе с клавиатурным биндом образует **OR** через общий debounce
  ~250 мс (§4.1). В UI — capture «нажмите кнопку» в поле `pad` (§4.4): первый
  DOWN пишет каноническое имя кнопки из device-info блока (`XboxX`) либо
  `unknown:<N>` — если метки нет; system-кнопки — `Guide`/`Share` (§4.1).
  Connect/disconnect — INFO (§4.1, §8). Без эмуляции
  клавиатуры. Linux — вне scope (см. ниже, §9).
- Захват экрана: **весь экран** (монитор с foreground-окном) и **окно**
  (захват содержимого окна независимо от z-порядка).
- Оверлей-уведомление (тост): успех и ошибка; ошибки видны всегда.
- Окно настроек (3 вкладки; строка `Apply | OK | Cancel` у нижней границы
  окна, значок статуса/предупреждения у своего контроля — §4.4).
- Работа в системном трее (скрытый запуск, контекстное меню).
- Конфиг `config.toml` по конвенциям OS, авто-создание дефолта при первом запуске.
- Шаблон пути файла с токенами: `%Y %y %mo %d %H %M %S %iso %t %n %ext`.
- Headless-подкоманда `virshot shot` для тестов.
- Single-instance guard (resident-приложение; lock-file рядом с used-config,
  stale-recovery по pid; `virshot shot` не блокируется — one-shot CLI для
  скриптов/E2E; разные `--config` — параллельные инстансы).

**Не входит в MVP (на будущее):**

- Геймпад на Linux — вне scope: `gilrs` не добавлен. Hardware-находка: wgi-бэкенд
  `gilrs` гейтит чтения по timestamp контроллера, а generic HID-геймпады отдают
  константный timestamp — нажатия не приходят (проверено на железе пользователя,
  pad vendor=1118 product=2835). На Linux/GameInput-нет-хоста поток не
  запускается, поле `pad` в UI — disabled placeholder; геймпад-триггер работает
  только на Windows. См. §3, §4.1, §9.
- Захват области (`rect`) — слоты в конфиге и UI зарезервированы, без реализации.
- Запись видео / Replay Buffer.
- Встроенный редактор изображений.
- Эксклюзивный полный экран — документированное ограничение (см. §9).
- Автозапуск при логине.
- Пользовательская иконка трея (в MVP — встроенная).
- i18n — UI локализован (реализовано 2026-11-06, v9): `rust-i18n` 4.2.4, каталог
  в одном файле `locales/app.yml` с `_version: 2` (76 ключей, вложенные блоки
  локалей под каждым ключом), локали `en`/`ru`/`zh-CN`/`es`/`ja`/`ko`; выбор
  языка — dropdown в General (§4.4), смена языка без перезапуска (§4.4, §4.5).
  Не переводятся: ключи конфига, CLI-текст (`--help`, stdout/stderr) и логи —
  английские (§8); документация/README — на русском; нотации — канонические
  (§4.4).
- macOS — вне scope.

## 3. Технический стек

- **Язык:** Rust (latest stable, rust version 1.99.1).
- **UI и Оверлей:** `eframe` / `egui` (multi-viewport для окна настроек и
  оверлея). Реализовано (Stage 8-9, перенесено в крейты в Stage 4): тост живёт
  в workspace-крейтах `crates/toast` (правила: `std`-таймер-поток, latest-wins,
  fade-out) и `crates/overlay` (бэкенд `OverlayHost` поверх `egui::Context`
  multi-viewport + чистая геометрия углов `place`). Плашка — дочерний viewport:
  transparency из ROOT-билдера (GL alpha), click-through (`mouse_passthrough`),
  always-on-top, content-protected, показ после первой отрисовки. `eframe` с
  `default-features=false, features=["glow","default_fonts","x11","wayland"]`
  (accesskit-стэки выключены для бюджета размера). Оба крейты — path-deps,
  новых crates.io зависимостей не добавлено (§4.3).
- **Геймпад (Windows — реализовано, v5):** свой crate `crates/gamepad` —
  hand-written COM shim над экспортами `gameinput.dll` (zero deps — `windows`
  crate не добавлен), подключён как path-dep в
  `[target."cfg(windows)".dependencies]`, так что на Linux зависимость не
  pull-ится вообще. Механика — как в PoC (`hidpad-poc/` остаётся историческим
  артефактом): focus policy перед регистрацией, QI-негосиация v3→v2→v0,
  dispatcher `Dispatch(5000µs)` на потоке-помпе + 50 ms опрос кнопок по
  **STATE-diff** (не timestamp-diff); событие библиотеки — маска состояния,
  DOWN-edges (0→1) считает virshot (`bits & !previous`). System-кнопки
  Guide/Share — через system-button-регистрации. Метки кнопок читаются из
  device-info блока (v3 `controllerInfo`→`controllerButtonLabels`,
  v2 `controllerButtonInfo`, v0 — меток нет): слота `GetButtonLabel` на
  `IGameInputDevice` в vendored header нет — это имя WinRT. unsafe: в virshot
  `#![forbid(unsafe_code)]`, в `crates/gamepad` — crate-root
  `#![deny(unsafe_code)]` с единственным исключением в `gameinput.rs`
  (COM-vtable нельзя воспроизвести без unsafe). Нестандартные кнопки —
  `unknown:<N>` (raw-номер), см. §4.1 и §9. Linux: `gilrs` вне scope
  (hardware finding — §2 и §9), поток не запускается, код под `#[cfg(windows)]`.
- **Захват экрана:** `xcap`.
- **Глобальные клавиатурные хоткеи:** `global-hotkey` (approved 2026-11-03;
  system-wide: PrintScreen работает, когда фокус у игры; регистрация на
  main-тред — pump от winit).
- **Системный трей:** `tray-icon` (ksni) — интегрирован (Stage 10): polling
  глобальных receivers в цикле eframe.
- **Диалог выбора папки:** `rfd` (стандартные native dialog на Windows/Linux) —
  approved пользователем 2026-11-03.
- **Локализация UI (v9):** `rust-i18n` 4.2.4 (new crates.io dep, approved
  пользователем в task `2026-11-06_i18n-translations`; без features) — каталог в
  одном файле `locales/app.yml` (`_version: 2`), init-макро на crate root
  (`src/main.rs:70`, `fallback = "en"` — иначе промах возвращает dotted-ключ),
  compile-edge `include_str!("../locales/app.yml")` (`src/main.rs:72-78`): без
  него правка перевода не вызывает rebuild (rust-i18n читает YAML на macro
  expansion, его build-script следит только за своим каталогом). Депенденсы
  pure Rust — Windows-gnu кросс-сборка работает (§2, §4.4).
- **Font-fallback для азиатских локалей (v9 follow-up):** без new crates.io dep —
  `egui::Context::add_font_provider` (`src/fonts.rs`): по скрипту непрокрытого
  глифа (Hangul / kana / CJK) читается системный шрифт Windows (`malgun.ttf`,
  `yugothic.ttf`, `msyh.ttc` — face index 0 для `.ttc`), результат кэшируется на
  скрипт и вставляется в конец fallback-цепочки семьи, поэтому латиница и
  кириллица остаются на Ubuntu-Light. Feature `system_fonts` у `eframe` остаётся
  выключенным (+0,53 МБ — отвергнуто пользователем), отсутствие файла даёт tofu
  как раньше (без паники), Linux-кандидаты — только для dev-host preview.
- **Конфигурация:** `serde` + `toml`.
- **Логирование:** `tracing` + `tracing-subscriber` (файловый appender).
- **CLI:** `clap`.

Разработка — в WSL (Linux-сборка компилируется и работает core-функции:
захват/сохранение/конфиг/CLI; GUI и хоткеи на Linux — best-effort по
возможностям окружения). Финальная приемка — вручную на Windows.

## 4. Функциональные требования

### 4.1. Модуль ввода (Геймпад + хоткеи)

- Глобальные клавиатурные хоткеи регистрируются system-wide hook'ом (работают
  при фокусе у игры). Ошибка регистрации (конфликт/недоступно) — статус в UI +
  лог, без падения; формулировка причины читаемая (для конфликта — «already
  registered by another application (…) — free that key or pick another»,
  для прочего — «registration failed: …»). Комбо, не зарегистрированные при
  старте, повторно регистрируются, когда окно настроек получает фокус (§4.4):
  на Windows foreground-окно может забрать комбо, занятое системным дефолтом
  (`RegisterHotKey`); на Linux X11-grab не вытесняется — повтор честно
  воспроизводит ту же ошибку (INFO/WARN в лог), UI-статус не «исправляется».
  Повтор чинит **занятые** комбо; **доставка нажатия** — отдельная проблема: на
  Windows `PrintScreen`/`ScrollLock`/`Pause` не приходят ни в один клавиатурный
  канал окна, и её обходит временная bind-проба (§4.4 v7). Отказ регистрации
  пробного комбо — WARN в лог, а не ошибка строки: значок у строки описывает
  только комбо самого действия, и если нажатие так и не пришло, строка остаётся
  несвязанной (`unbound — click to bind`), не «с ошибкой».
- Геймпад-поток (Windows — реализовано): отдельный поток-помпа `gameinput.dll`
  (`crates/gamepad`, §3, §6), plug-and-play; connect/disconnect устройства —
  INFO (§8); при отключении устройства поток не падает; если GameInput
  недоступен при старте — INFO и приложение продолжает работать (ошибки —
  значения, не паника). На Linux/GameInput-нет-хоста поток не запускается
  (INFO на старте), бинды из `config.toml` там не срабатывают.
- Каждое действие («весь экран», «окно», «область» [зарезервировано]) имеет
  **два поля бинда: Основное и Дополнительное**.
  - В MVP поле хранит **клавиатурную комбо** (клавиша + произвольный набор
    модификаторов Ctrl/Alt/Shift, напр. `Alt+PrintScreen`).
  - Поле «кнопка геймпада» (`pad`) — реализовано на Windows (`pad = null` —
    бинд не задан): значение — **одна** кнопка геймпада (комбо из нескольких
    кнопок геймпада **не поддерживается**). Нотация (case-insensitive):
    каноническое имя кнопки из device-info блока GameInput (`XboxA`..`XboxY`,
    `XboxDPad*`, `XboxLeftShoulder`/`XboxLeftTrigger`/`XboxLeftStickButton`,
    `XboxPaddle1`..`4`, буквенные/цифровые, стрелочные и иконные имена,
    generic console-имена `Back`/`Start`/`Select`/`Options`/`Menu`/`View`/
    `LB`/`LT`/`LSB`/`L1`..`L3`/`RB`/`RT`/`RSB`/`R1`..`R3`/`Paddle*`) — индекс
    кнопки резолвится в момент выстрела по таблицам меток подключённых
    устройств (первое устройство, отдающее это имя), поскольку индекс зависит от
    модели (§9); `unknown:<N>` — raw-номер кнопки (`N` = 0..63) для устройств
    без меток; `Guide` / `Share` — system-кнопки (в device-info их нет — имя и
    есть нотация). Legacy gilrs-имена (`North`, `East`, `South`, `West`,
    `LeftShoulder`, `RightShoulder`, `LeftTrigger`, `RightTrigger`,
    `RightThumbStick`, `LeftThumbStick`, `LeftStick`, `RightStick`)
    поддерживаются ради конфигов до Stage 5: для них индекс зафиксирован
    таблицей (это допущение, не истина железа). Имя, которое ни одно
    подключённое устройство не отдаёт, не срабатывает и фиксируется в лог
    одной WARN на имя (§9) — отдельного предупреждения в UI нет.
    В capture-режиме бинда «нажмите кнопку» кнопка записывается именем метки из
    device-info (`XboxX`), при отсутствии метки — `unknown:<N>` с номером из
    события (при нескольких новых нажатиях, пойманных одним опросом, —
    наименьший номер), system-кнопка — как `Guide`/`Share`.
  - Поля заполняются независимо; **действие срабатывает по любому заполненному
    полю (OR)**; клавиатурный и геймпад-источник выстреливают через **один
    общий debounce-гейт** на действие — один снимок, а не по одному на источник.
- Бинд в UI: клик по полю → capture-режим «нажмите клавишу» (не dropdown);
  клик по полю `pad` (Windows) → capture-режим «нажмите кнопку»: первый DOWN
  фиксирует бинд и завершает capture. `Esc` отменяет capture **обоих** полей
  (строка не меняется), `Backspace` очищает бинд того поля, которое сейчас в
  capture: keyboard — клавиатурную половину (pad остаётся), pad — слот
  геймпада (клавиатура остаётся); очищенная клавиатурная строка показывает
  `unbound — click to bind`, и сохранение с ней заблокировано (§4.4).
  Повторный клик по тому же полю тоже отменяет capture. Пока любое бинд-поле
  находится в capture, геймпад-выстрелы подавляются. Список подключённых
  геймпадов в UI не делается (YAGNI).
- **Debounce** одного действия ~250 мс (повторный триггер короче интервала
  игнорируется) — один гейт на оба источника (§4.1 OR-fire).

### 4.2. Модуль захвата экрана

- **Мишень захвата** определяется в момент триггера по foreground-окну;
  собственные окна приложения (настройки/оверлей) исключены из анализа.
- **Весь экран** — монитор, на котором находится foreground-окно; если
  foreground не определён — fallback на primary монитор.
- **Окно** — захват содержимого foreground-окна независимо от перекрытия
  (на Windows — PrintWindow). Если активного окна нет (виден desktop) —
  **ошибка** («no active window») в тост и лог, файл не сохраняется; неудача
  захвата — тоже ошибка в тост и лог.
- Форматы: `png` (дефолт, без потерь), `jpg` (качество, дефолт 90),
  `webp` (качество, дефолт 90; в MVP — lossless VP8L, lossy перенесён:
  требует нативный dep с approval пользователя). Формат — **глобальная настройка**.
- **Шаблон имени файла** (см. §7): токены `%Y %y %mo %d %H %M %S %iso %t %n %ext`;
  `%iso` = `YYYY-MM-DD_HH-mm-ss`, время — **локальное**.
  - `%t` — в window-шаблоне: заголовок окна, в full-screen шаблоне: литерал `fullscreen`.
  - `%n` — счётчик коллизий в целевой папке (обычно 1), определяется
    сканированием папки на диске при сохранении (без state-файла).
  - `%ext` — расширение выбранного формата (`png`/`jpg`/`webp`).
- **Санитизация:** недопустимые символы в `%t` → `-`, пустой заголовок → `untitled`,
  обрезка до ~60 символов; сегменты шаблона санитизируются.
- **Валидация шаблона:** только относительный путь от `save_path`; абсолютные
  пути и сегменты `..` запрещены, неизвестный токен отвергается
  (`template::Error`). Проверка выполняется при рендере имени в момент захвата
  (`template::render`) — отдельной валидации в UI нет: невалидный шаблон даёт
  ошибку захвата «invalid filename template: …» в тост и лог, файл не
  сохраняется. Справочник токенов в UI (§4.4) генерируется из
  `template::TOKENS` (11 токенов с описаниями) и новых ключей конфига не
  добавляет.
- **Коллизии:** перезапись запрещена; при совпадении добавляется суффикс
  `-2`, `-3`… перед расширением (если `%n` в шаблоне — его значение).
- Отсутствующие подпапки шаблона создаются автоматически.
- Сохранение выполняется в отдельном потоке (без микро-фризов в игре).

### 4.3. Оверлей-уведомление (тост)

- Реализация (Stage 4, план overlay/toast): машинерия тоста вынесена в
  workspace-крейты — `crates/toast` (правила тоста на `std`-таймер-потоке:
  `ToastService`, `ToastHandle`, latest-wins) и `crates/overlay` (бэкенд
  хост-цикла `OverlayHost` поверх `egui::Context` multi-viewport + чистая
  геометрия углов `place`). Собственный модуль `src/overlay.rs` и весь
  toast-код в `src/gui.rs` удалены; правила ниже не изменились.
- **Владелец:** `SettingsApp` хранит `overlay::OverlayHost` и
  `toast::ToastService`; оба создаются в `create`-замыкании eframe в `gui::run`
  и живут до конца цикла. Порядок объявления полей — сервис **до** хоста:
  `Drop` сервиса (Quit + join потока, закрытие плашек) выполняется, пока хост
  ещё жив.
- **Передача handle:** `capture::ToastHandoff` — latest-only слот
  `Arc<Mutex<Option<ToastHandle>>>`. `gui::run` заполняет его в `create`;
  потоки-триггеры (хоткеи, геймпад, трей) читают слот на каждый захват.
  Handle передаётся capture **отдельным параметром** `run_capture`/`spawn_capture`,
  а не внутри `CaptureCommand`. Пустой слот (headless `virshot shot`, либо
  захват до/после GUI) — уведомления нет: CLI печатает путь в stdout и пишет
  результат в лог.
- **Рисование:** плашка — дочерний egui-viewport, созданный бэкендом:
  прозрачное окно без decorations, always-on-top, **mouse passthrough**
  (клики проходят в игру), **content-protected**. Окно создаётся скрытым
  (`with_visible(false)`, `with_active(false)` — показ без захвата фокуса),
  рисуется пока скрыто (`RequestPaintWhileHidden`) и показывается
  `Visible(true)` только после первой отрисовки — белой «тени» DWM нет.
  `OverlayHost::update(&ctx)` вызывается из `App::logic`, поэтому плашки
  появляются и гаснут и при скрытом окне настроек (на скрытом окне eframe
  выполняет `Context::run_logic`, чей `LogicOutput` содержит команды всех
  viewport'ов). Ограничения платформ те же: Wayland — позиция и always-on-top
  игнорируются (композиционер), passthrough работает; X11 — transparency только
  при создании окна.
- **Click-through на Windows игнорируется** в обоих бэкендах (`OverlayHost`
  и thread-бэкенд): winit 0.30.13 `set_cursor_hittest(false)` добавляет
  `WS_EX_LAYERED` без `SetLayeredWindowAttributes` — окно без layered-атрибутов
  не композитится (плашка не рисуется вовсе), поэтому флаг гасится на Windows
  (`cfg!(windows)`). Плашка не интерактивна — потеря passthrough безвредна.
  На Linux/macOS passthrough работает (X11 — input-shape).
- **Замена:** новый тост заменяет текущий (не стек), ровно одна плашка на
  монитор; spawn/закрытие выполняет бэкенд, app не управляет окнами.
- **Анимация:** fade-in отсутствует (плашка рисуется с полного непрозрачного
  первого кадра), fade-out фиксированный ~250 мс; удержание = `duration_ms`
  (дефолт 2000 мс); `duration_ms = 0` — плашка без авто-скрытия; ошибки
  держатся ~3000 мс независимо от `duration_ms`.
- **Позиция:** 4 угла экрана (`position = TopLeft|TopRight|BottomLeft|BottomRight`
  → `overlay::Corner`), фиксированные отступы 30 px от вертикальной границы и
  60 px от горизонтальной; нижние углы очищаются от панели задач запасом ~48 px.
  Вся математика — `overlay::place` (константы `CORNER_INSET_X`,
  `CORNER_INSET_Y`, `TASKBAR_CLEARANCE`); вариант с `GetMonitorInfo.rcWork`
  (`windows-sys`) отклонён ранее — unsafe FFI.
- **Мониторы:** геометрия берётся один раз при старте GUI на main-потоке —
  `xcap::Monitor::all()` (никогда не в hot-path захвата), переведённая в
  **LOGICAL точки** делением на `ctx.pixels_per_point()` (egui умножает
  позицию/размер builder'а на масштаб), **primary — первым**. `on_all_monitors`
  (дефолт `true`) → `MonitorSel::All` (тост на каждом мониторе, тот же угол);
  `false` → `MonitorSel::Index(0)` (primary). Fan-out корректен: ровно одна
  плашка на каждый монитор. Ошибка перечисления или пустой
  список — WARN/лог, плашки не показываются, приложение живёт; геометрия
  мониторов не обновляется при hotplug (снимок при старте). Debug-пример
  `toast_debug` использует ту же конвенцию: перечисляет **все** мониторы
  (`winit available_monitors()` ÷ `pixels_per_point()` корня) — раньше
  перечислял только primary. Caveat mixed-DPI: все physical-rects делятся на
  один root `pixels_per_point` — при разных DPI мониторов плашка на вторичном
  мониторе может встать неверно (отдельное решение, вне этой задачи).
- **Триггер:** тост срабатывает **только после скриншота** (успех
  захвата-сохранения либо ошибка), не на хоткей-событие. Показ/мониторы —
  INFO-лог для диагностики на Windows.
- **Содержимое (локализуется, v9):** успех — `Saved: <имя файла>` (полный путь
  остаётся в лог) с `ToastColor::Success`; формулировка чипа берётся из каталога
  `toast.saved` (`%{file_name}`) — под `ru` это «Сохранено: <имя файла>»
  (`capture::saved_text`, `src/capture.rs:255-258`); ошибка — текст ошибки с
  `ToastColor::Danger`, формулировка из каталога `toast.*` по типовой ошибке
  (`capture::chip_text`, `src/capture.rs:268-308`), техническая деталь (`path`,
  `reason`) — английская внутри `%{...}`. `Error: Display` остаётся английским:
  лог и headless CLI печатают его как раньше (§2, §8). Гейт прежний: успех
  показывается только при `overlay.enabled = true`, ошибки показываются **даже
  при `overlay.enabled = false`** (чистая функция `capture::should_show`).
- **Тест плашки (§4.4, вкладка Overlay):** кнопка «Test overlay» публикует
  плашку через тот же `capture::ToastHandoff` / `toast::ToastHandle`: текст
  `Saved: test.png` — тем же `capture::saved_text`, что и реальный успех
  (локализуется: под `ru` — «Сохранено: test.png», `test.png` не переводится),
  цвет Success, угол/мониторы/удержание — из текущего draft (тестируются и
  несохранённые настройки). Захват, запись файла, правка конфига и
  перерегистрация хоткеев не выполняются; кнопка активна только при
  `enabled = true` (иначе disabled с hint).
- Ключи конфига неизменны: `[overlay] enabled`, `position`, `duration_ms`,
  `on_all_monitors`.
### 4.4. Окно настроек (GUI)

- Обычное окно с рамкой; дефолтный размер ~720×520; позиция/размер не сохраняется.
  Chrome — только крестик: кнопки minimize/maximize выключены
  (`ViewportBuilder::with_minimize_button(false)` / `with_maximize_button(false)`),

- Закрытие крестиком — программа прячется в трей (не завершается);

- **Строка `Apply | OK | Cancel` у нижней границы окна** — реальный

    (перерегистрация хоткеев, публикация настроек для pad-помпа); окно
    остаётся открытым.
  - **OK** — тот же `apply()` + реальное закрытие окна (не hide-to-tray).
  - **Cancel** — отбрасывает draft (ничего не сохраняется и не публикуется),
    отменяет активный bind-capture и закрывает окно так же, как OK.
  - Apply/OK disabled, пока draft не изменён, и пока не пройдены два гейта
    сохранения: во всех строках задана клавиша (`draft_savable`) и триггеры
    уникальны (`duplicate_bindings` — ниже). Тултип disabled-кнопки называет
    блокирующий гейт; Cancel активен всегда.
- **Язык UI (v9):** dropdown «Language» — **первая строка** вкладки "General",

  (`general.language`, §7). Порядок Apply: сохранение `config.toml` →
  `rust_i18n::set_locale` → пересборка меню трея (`src/gui.rs:1448-1466`,
  `tray::TrayController::refresh_menu`) — текст UI меняется без перезапуска;
  отказ пересборки меню — WARN в лог, приложение живёт (§5). Локализуется только
  текст UI: нотации остаются каноническими — имена клавиш (`Ctrl+PrintScreen`,
  `PrintScreen`, `Escape`), `+`, pad-нотация (`unknown:<N>`, `Guide`, `Share`),
  токены шаблона (`%Y/%y/%mo/%d/%H/%M/%S/%iso/%t/%n/%ext`), `png/jpg/webp`,
  имена углов, sentinel-значения `fullscreen`/`untitled`, `OK`, `virshot`
  (в title — `virshot — <локализованное слово>`), единица длительности (`" ms"`,
  `ru` — `" мс"`, `zh-CN` — `" 毫秒"`).
1) **Вкладка "General":**
   - Корневой путь сохранения (`save_path`, кнопка **Browse** — стандартное
     диалоговое окно выбора папки; crate `rfd` — **new dep, требует approval**).
     Стартовый путь диалога: `save_path`, если существует, иначе
     `%USERPROFILE%\Pictures` (на Linux — `~/Pictures`).
   - Дефолт `save_path` резолвится при старте из home-каталога:
     `%USERPROFILE%\Pictures\ViRShot` (Linux — `~/Pictures/ViRShot`) — вместо
     хардкода пути.
   - Шаблон full-screen: дефолт `FullScreen/%y-%mo/%iso.%ext`.
   - Шаблон окна: дефолт `%t/%y-%mo/%t-%iso.%ext`.
   - Справочник токенов (`Placeholder reference`) — свёрнутый по умолчанию
     `CollapsingHeader` под полем window-шаблона: строки берутся из
     `template::TOKENS` (11 токенов с описаниями) — это справка, не контроль;
     отдельной валидации шаблона в UI нет (§4.2).
   - Формат файла; `jpeg_quality`; `webp_quality`.
2) **Вкладка "Hotkeys":**
   - 3 колонки в одном `egui::Grid` (Действие | клавиша | геймпад): колонки
     выровнены по всей вкладке, кнопка бинда — фиксированная минимальная
     ширина.
   - Действия: `Full screen` (PrintScreen), `Window` (Alt+PrintScreen),
     `Rect area` (Ctrl+PrintScreen — слот зарезервирован, неактивен в MVP;
     строка рендерится disabled, не входит в capture и не участвует в
     сравнении дубликатов).
   - Поле бинда = **кнопка с текущим биндом** (текст `Alt+PrintScreen` и т.п.,
     очищенная клавиша — `unbound — click to bind`); клик → bind-by-press
     (новая комбинация заменяет клавиатурную половину строки, pad остаётся).
     Селект клавиши и чекбоксы модификаторов убраны; нотация в конфиге — без
     изменений. Связываемый набор = коды, которые egui отдаёт как `Event::Key`
     **и** которые `global-hotkey` может зарегистрировать на Windows
     (`SUPPORTED_KEY_NAMES`) — плюс клавиши временной bind-пробы на Windows
     (описаны ниже): `PrintScreen`, `A`–`Z`, `0`–`9`, `F1`–`F24`,
     стрелки, `Insert`/`Delete`/`Home`/`End`/`PageUp`/`PageDown`,
     `Space`/`Enter`/`Tab`, punctuation с физическим кодом (`Comma`..`BracketRight`,
     `IntlBackslash`), `ContextMenu`, `Pause`/`ScrollLock`/`Help`/`Sleep`,
     browser-, media-, volume- и launch-клавиши. Прочие нажатия во время capture
     игнорируются.
     Config-only коды (`MediaPlay`/`MediaPause`/`MediaSelect`,
     `Convert`/`KanaMode`/`NonConvert`, `IntlRo`/`IntlYen`, `Numpad*`) связываются
     только правкой `config.toml` — в UI они не связываются (§9).
     `Escape`/`Backspace` зарезервированы для capture-UI, модификаторы как
     основная клавиша и локи `CapsLock`/`NumLock` не связываются (§2, §9);
     `ScrollLock` с v7 связываемый (§2).
     На время capture-press все глобальные хоткеи временно **отключаются**
     (иначе нажатие нашей же зарегистрированной комбо стрельнет скриншотом
     вместо бинда), после commit/cancel — восстанавливаются из применённого
     конфига. `Esc` отменяет capture, `Backspace` очищает клавиатурную половину
     строки (§4.1).
     **Bind-проба (v7, Windows).** Отключения хуков недостаточно: Windows не
     присылает в egui нажатия `PrintScreen`, `ScrollLock`, `Pause` — для
     `VK_SNAPSHOT` нет `WM_CHAR`/`WM_DEADCHAR`, а winit 0.30.13 откладывает
     keydown до char-сообщения и сбрасывает сохранённый `PartialKeyEventInfo` на
     следующем keydown (`platform_impl/windows/keyboard.rs:106-155`, `:124-125`);
     регистрация при этом успешна (`Hotkey registered: PrintScreen
     (full_screen)`) — это дефект **доставки**, не регистрации. Поэтому сразу
     после отключения хуков регистрируются временные **пробные** комбы клавиш из
     расширяемого списка `hotkeys::PROBE_KEYS` (`PrintScreen`, `ScrollLock`,
     `Pause`) — наборы модификаторов `bare`, `Alt`, `Ctrl`, `Shift`, `Alt+Shift`,
     `Ctrl+Shift` (`Win` отсутствует: winit не отдаёт Super, такую комбу
     нажатием всё равно не связать). Выстрел пробной комбо **не** делает
     скриншот: слушатель распознаёт пробный id раньше карты действий (bare-проба
     делит id с bare-биндом того же клавишного действия), записывает `key`/`mods`
     в latest-only слот и будит цикл eframe; GUI в logic-pass коммитит нажатие в
     строку так же, как обычное egui-нажатие: `key` и `mods` **заменяются**,
     `pad` остаётся, capture завершается, и пробные регистрации снимаются
     **перед** `restore()`. Проба живёт ровно столько, сколько открыт
     keyboard-capture: `start_bind_probe` на его старте, `stop_bind_probe` перед
     restore/Apply; только на Windows (`cfg!(windows)`) — на Linux проб не
     создаётся, эти клавиши приходят через egui как обычные key-события. Отказ
     пробной регистрации — WARN в лог, комбо остаётся вне пробной карты (§4.1,
     §8).
     **Цена обхода:** пока строка в keyboard-capture, bare PrintScreen
     перехватывается пробой — системный Snipping Tool в этот момент не
     срабатывает; если пробная комба не зарегистрировалась, Snipping Tool
     работает как обычно. В простое (capture закрыт) поведение ОС не меняется.
     Ограничения: модификатор `Win` недостижим из bind-by-press (winit
     не отдаёт Super) — задаётся правкой config.toml; clipboard-комбо
     `Ctrl+Insert`/`Shift+Insert`/`Shift+Delete` не связываются — egui-winit
     обрабатывает их как clipboard-команды до `Event::Key` (§9).
   - Значок привязан к своему контролю (§4.4): предупреждение клавиатуры — сразу
     **слева от кнопки бинда**, предупреждение геймпада — сразу **слева от поля
     `pad`**, источник у каждого только свой (клавиатурная коллизия не помечает
     pad и наоборот). Коллизия бинда приоритетнее статуса регистрации (draft —
     то, что отправляется на Apply). Slot значка резервируется в каждой строке
     (в т.ч. пустой), поэтому колонки не «прыгают»: треугольник из встроенной
     текстуры, fallback — ASCII `!` в том же slot, тултип на самом значке.
   - Ошибка регистрации (конфликт и т.п.) — значок предупреждения у кнопки
     бинда, читаемая причина — в тултипе (§4.1); инлайн-текст ошибки убран.
     Резерв `rect` — info-значок в колонке Действие с тултипом; `Registered` —
     без значка. Статусы — также в лог, включая повторную попытку при получении
     окном фокуса (§4.1).
   - **Коллизии триггеров:** одинаковая клавиатурная комбо на двух активных
     строках (сравнение нормализованное — регистр, порядок и дубликаты
     модификаторов) либо одинаковая pad-нотация (case-insensitive) — значок на
     каждом затронутом контроле и блокировка Apply/OK («one combo or pad button
     must trigger only one action»); `apply()` дополнительно отказывает и пишет
     коллизии в лог (гейт сохранения, §4.4). Строка `Rect area` в сравнении не
     участвует.
   - В начале формы — одна строка-hint «Esc to cancel, Backspace to clear»; с v8
     она рисуется на каждом кадре, независимо от того, активен ли capture
     (формулировка общая, не зависит от поля: `Esc` отменяет, `Backspace` очищает).
   - Поле кнопки геймпада (`pad`) — реализовано на Windows (§4.1): клик по нему
     → capture-режим «нажмите кнопку» (кнопка `Press a button…`, незаполненное
     поле — `pad — click to bind`); первый DOWN пишет нотацию
     (`XboxX` / `unknown:<N>` / `Guide` / `Share`) в draft (публикуется только
     Apply) — метка кнопки из device-info теперь и есть нотация, отдельный
     hint рядом не рисуется. Отмена — `Esc`, повторный клик по тому же полю или
     старт keyboard-capture; `Backspace` очищает pad-слот (клавиатурная
     половина остаётся). Во время pad-capture геймпад-выстрелы подавлены,
     клавиатурные хоткеи остаются активны (пауза регистраций относится только к
     keyboard-capture). На хосте без GameInput поле — disabled placeholder
     «(gamepad — Windows only)».
   - Если контроллер хоткеев на этом хосте отсутствует, внизу вкладки — строка
     «Hotkeys unavailable on this host (see log)».
3) **Вкладка "Overlay":**
   - `enabled`, угол экрана, `duration_ms`, `on_all_monitors`.
   - Кнопка «Test overlay» — рядом с чекбоксом `Show overlay toast`: активна
     только при `enabled = true` (иначе disabled с hint «Enable the overlay
     toast to test it»); публикует плашку `Saved: test.png` через тот же
     handoff с настройками текущего draft (§4.3) — конфиг и диск не
     затрагиваются.
   - Строка результата теста (INFO «Overlay test toast shown: … (no file
     written)») — в статусной зоне под вкладкой, не внутри формы.

- Левый клик — открыть окно настроек.
- Правый клик — меню: `Take screenshot` (захват всего экрана), `Settings`, `Exit`,
  `About` (4-й пункт после `Exit`, task `2026-11-10_about-dialog`). Метки меню на

  на Apply (`tray::TrayController::refresh_menu`) — без

### 4.6. Окно «О программе» (About)

- Пункт `About` из меню трея открывает дочерний viewport (`show_viewport_deferred`,
  id `virshot-about`) на том же eframe-цикле — второй `EventLoop` не создаётся (§6).
  Регистрация — каждый logic-pass пока окно живо (незарегистрированный pass его
  закрывает; механика та же, что у тост-чипов §4.3), закрытие крестиком снимает флаг.
- Хром окна — системный: заголовок `about.title` (каталог `about.*`), рамка
  ресайза и кнопка закрытия включены (`ViewportBuilder::with_resizable`,
  `with_close_button`); кнопки «свернуть» и «развернуть» сняты
  (`with_minimize_button(false)`, `with_maximize_button(false)` — winit
  `WindowAttributes::with_enabled_buttons`). На Windows и macOS их действительно
  нет; на X11 и Wayland winit 0.30.13 документально не применяет этот флаг, поэтому
  там они остаются — это ограничение платформы, не дефект окна. Проверка «кнопок
  нет» — на реальном Windows (отложена, §9).
- Закрытие — системной кнопкой окна (или вместе с выходом из приложения): запрос
  закрытия фиксируется в paint-pass'е дочернего viewport в общий флаг, следующий
  logic-pass снимает регистрацию, eframe сбрасывает `Arc<Window>` и окно
  уничтожается; приложение остаётся живым в трее (§4.5), окно настроек не
  затрагивается. `ViewportCommand::Close`/`CancelClose`/`Visible(false)` для
  дочерних viewport не используются.
- Повторный выбор `About` в меню трея не закрывает и не дублирует окно: уже
  открытое окно поднимается наверх
  (`ctx.send_viewport_cmd_to(about_viewport, ViewportCommand::Focus)`).
- Заголовок: иконка приложения (текстура из `icons::APP_ICON_PNG`, загружается
  один раз и принадлежит `SettingsApp`) + крупный `ViRShot <версия>` (ключ
  `about.app_title`).
- Под заголовком — ссылка на репозиторий (`about.repo_link`, `ui.hyperlink_to`,
  URL `https://github.com/Apkawa/virshot` записан в коде, т.к. в манифестах
  `repository` нет). Набор ссылок расширяется отдельной задачей.
- Под ссылками — одна строка билда: `<short sha> <date>` (`shadow-rs`
  `SHORT_COMMIT`, дата в Москве `+03:00` из `cargo:rustc-env=VIRSHOT_BUILD_TIME`,
  алгоритм `civil_from_days` в `build.rs`); пустые значения печатаются как
  `unknown`. Маркер сборки `debug|release` убран, ключи
  `about.marker_debug`/`about.marker_release` удалены из каталога. Отдельные
  строки «Версия», «Коммит», «Ветка» больше не показываются.
- Версия (заголовок и `--version`) получает суффикс `-dev`, если HEAD не несёт
  релизный тег `v<version>`: локальная сборка (в том числе `--release`) и nightly
  без тега релиза показываются как `0.1.0-dev`. Ориентир — коммит с тегом версии
  (`shadow-rs` `TAG` из `git tag -l --contains HEAD`, в CI — из `GITHUB_REF`);
  `build.rs`, CI и `scripts/release.sh` не меняются.
- Фон окна непрозрачный: `egui::CentralPanel` с `Frame::central_panel(style)`
  (`visuals.panel_fill`) и отступами `Margin::symmetric(16, 8)`; `App::clear_color`
  остаётся прозрачным, потому что тост-чипы и оверлей-viewport'ы (§4.3) требуют
  прозрачной поверхности.
- Все тексты — каталог `about.*` (§2), интерполяция `%{...}`; `about.app_title`
  — бренд-нотация, печатается одинаково во всех локалях.
- Ниже — весь `CHANGELOG.md` (`include_str!`), рендерится `egui_commonmark` в
  прокручиваемой области; пустой changelog — локализованный placeholder.
- Клик по ссылке открывает системный браузер (`eframe` feature `links` →
  `egui-winit` → `webbrowser`: `xdg-open` на Linux, обработчик реестра на
  Windows). Само приложение не делает сетевых запросов (§5). `Exit` из меню
  закрывает root viewport — eframe гасит дочерние окна на shutdown. В
  headless-режиме (GUI недоступен) запрос `About` — WARN в лог (§8-поведение
  трея без GUI).

## 5. Нефункциональные требования

- **Размер бинарника:** < 10 МБ (release: `strip`, `lto`, `opt-level="z"`).
  Азиатский font-fallback (§3) байтов не добавляет — шрифт читается из системы.
- **RAM:** < 30 МБ в фоне (без захвата). **CPU:** < 1% при простое. Ленивый
  font-fallback догружает один файл на скрипт (порядка 5–20 МБ на heap) только
  пока азиатский текст на экране — при `en`/`ru` расход 0.
- **Безопасность:** никаких сетевых запросов из процесса приложения (ссылки
  открывает системный браузер); полная приватность.
- **Отказоустойчивость:** любая ошибка (нет доступа к папке, ошибка регистрации хоткея,
  неудачный захват) логируется и показывается тостом — без аварийного завершения.

## 6. Архитектура и потоки (Threading)

Модель (итог — Stage 6-10):

1. **Main Thread (UI + трей + регистрация хоткеев):** цикл `eframe` (окно
   настроек + оверлей: `overlay::OverlayHost` и `toast::ToastService` владеет
   `SettingsApp`, хост обновляется в logic-pass — плашки живут и при скрытом
   окне), polling событий трея каждый кадр, регистрация hotkeys (WM_HOTKEY
   thread-affinity, pump — winit). В `create`-замыкании handle сервиса
   кладётся в `capture::ToastHandoff` (§4.3).
2. **Input Thread (Hotkeys):** слушатель глобального receiver событий хоткеев →
   debounce → команда (owned `CaptureCommand`) + handle из `ToastHandoff`
   (читается на каждый выстрел) в capture-поток.
   **Gamepad Pump Thread (Windows):** поток-помпа `gameinput.dll`
   (`crates/gamepad`) — события → diff масок состояний (0→1 edges) →
   сопоставление с `pad`-биндом → **тот же общий debounce-гейт** (~250 мс на
   действие, §4.1) → та же команда + тот же handle в capture-поток. Связь с
   остальными модулями — mailbox-ы без callback в GUI: settings-mailbox (живой
   конфиг после Apply — re-bind выстреливает без перезапуска) и pad-capture
   mailbox (§4.4). Поток резидентен на весь процесс (stop-флаг не выставляется —
   parity с hotkeys-слушателем). На не-Windows хостах поток не запускается.
3. **Capture Thread:** принимает команду, захватывает (monitor/window), сохраняет
   файл; уведомление — через `ToastHandle` (отдельный параметр, не поле
   команды); при `None` (headless CLI, либо захват без GUI) — только лог и
   stdout.
4. **Toast Timer Thread (`crates/toast`):** таймер-поток крейта — latest-wins,
   удержание/fade-out, закрытие плашек через sink (`OverlayHostHandle`);
   `Quit` + join при drop сервиса (поле app объявлено раньше хоста).

Клавиатурные хоткеи: регистрация на main-тред (thread-affinity WM_HOTKEY на
Windows; X11 pump — свой поток крейта на Linux), слушатель событий — отдельный
поток (blocking receiver), debounce 250 мс per-action.

## 7. Формат конфигурации (config.toml)

Путь (портабельный режим): Windows — `config.toml` рядом с `virshot.exe`
(и `virshot.log` рядом); если каталог exe недоступен для записи — fallback
`%APPDATA%\virshot\`. Linux — `~/.config/virshot/config.toml` (XDG).
Переопределяется `--config`. При первом запуске создаётся дефолтный конфиг.
Неспарсенный/битый конфиг → ошибка в лог + работа на дефолтах. Значение
`general.language` нормализуется снисходительно (`config::language_code`,
`src/config.rs:121-129`): неизвестное/битое значение → `en`, остальные настройки
сохраняются (строгий enum сбросил бы весь конфиг на дефолты); полностью
неспарсенный TOML — как раньше (дефолты + ERROR-лог).

Схема (финальная; нотация клавиш — коды `Code` без регистра, модификаторы
`alt/ctrl/shift/win`, `Escape`/`Backspace` как клавиша бинда отвергаются
парсером — §2, §4.4; `pad` — бинд кнопки геймпада, активен на Windows, §4.1):

```toml
[general]
language         = "en"          # en | ru | zh-CN | es | ja | ko (первый ключ [general]; неизвестное значение → en)
save_path       = "%USERPROFILE%\\Pictures\\ViRShot"  # резолвится при старте из home
file_full_screen = "FullScreen/%y-%mo/%iso.%ext"
file_window      = "%t/%y-%mo/%t-%iso.%ext"

format      = "png"        # png | jpg | webp
jpeg_quality = 90
webp_quality = 90

[controls.full_screen]
key  = "PrintScreen"
mods = []          # ["Alt"], ["Ctrl","Shift"] ...
pad  = null        # canonical имя из device-info (напр. "XboxA") либо legacy gilrs-имя; "unknown:<N>" (кнопка без метки) или "Guide"/"Share"

[controls.window]
key  = "PrintScreen"
mods = ["Alt"]
pad  = "unknown:16"  # пример кнопки без метки (номер проверяется на железе)

[controls.rect]          # зарезервировано, неактивно в MVP
key  = "PrintScreen"
mods = ["Ctrl"]
pad  = null

[overlay]
enabled         = true
position        = "BottomRight"   # TopLeft | TopRight | BottomLeft | BottomRight
duration_ms     = 2000
on_all_monitors = true
```

## 8. CLI

Флаги: `--config`, `--log`, `--log-level=DEBUG|INFO|ERROR`, `--version`, `--help`.

- `--version` печатает contract-строку (task `2026-11-10_about-dialog`):
  `virshot <version> (<short-sha>) built <build-time>` — `<version>` из манифеста
  (`shadow-rs` `PKG_VERSION`), суффикс `-dev` если HEAD не несёт релизный тег
  `v<version>` (`shadow-rs` `TAG`; меняется только токен `<version>`),
  `<short-sha>` — короткий коммит (git через CLI),
  `<build-time>` — дата сборки в Москве в ISO 8601 с `+03:00` (`build.rs`,
  `VIRSHOT_BUILD_TIME`). Отсутствующие git/время печатаются как `unknown`
  (ни пустых скобок, ни пустого поля). stdout, exit 0.

Подкоманда (headless, для тестов захвата):

```
virshot shot [--window] [--out <path>] [--format png|jpg|webp]
```

- Без GUI/трея/оверлея; конфиг — источник дефолтов; `--out`/`--format` переопределяют.
- Печатает сохранённый путь в stdout; exit 0 — успех, 1 — ошибка.

Логи: по умолчанию `virshot.log` рядом с конфигом; `--log` переопределяет;
`--log-level` дефолт `INFO`; без ротации. Успешные сохранения — INFO;
connect/disconnect геймпада — INFO (Windows); выстрел с геймпада и фиксация
pad-бинда в UI — INFO. Отказ регистрации хоткея при старте — ERROR с читаемой
причиной и hint про повтор (§4.1); повтор при получении окном настроек фокуса —
INFO при успехе / WARN при повторном отказе. Отказ Apply из-за коллизий
триггеров — WARN; pad-имя, которое ни одно подключённое устройство не отдаёт —
одна WARN на имя (§4.1). Bind-проба (v7, Windows): INFO «Bind probe active (N
combo(s)) for PrintScreen, ScrollLock, Pause» на старте keyboard-capture (`N` —
сколько комб реально зарегистрилось; список клавиш — всегда полный список проб)
и INFO «Bind probe stopped (N combo(s) unregistered)» на его завершении
(пишется только если что-то было зарегистрировано); отказ пробной комбо — WARN
«Bind probe registration failed (<combo>): already registered by another
application (<combo> is held elsewhere) — free that key or pick another» (для
прочего — «registration failed: …»); неудачное снятие пробной комбо — WARN
«Bind probe unregister failed (<combo>): …»; нажатие пробной комбо — DEBUG
«Bind probe press recorded: <combo>»; фиксация бинда в строке — INFO «Probe bind
set for <action>: <combo>»; скинутое нажатие (capture уже закрыт или имя не
связывается) — DEBUG «Bind probe press dropped: <key> is not capturing» / «Bind
probe press dropped: <key> has no bindable name». DEBUG видны с
`--log-level=DEBUG`.

## 9. Ограничения (документируем в README)

- **Exclusive fullscreen не поддерживается:** захват может быть чёрным, оверлей
  не виден. Рекомендация — Borderless Windowed. Workaround не делаем.
- **Linux — best-effort:** core (захват/конфиг/CLI) работает; GUI работает на
  X11/Wayland; глобальные хоткеи — только X11 (Wayland не поддерживается
  крейтом — typed-ошибка при старте); трей — X11/D-Bus session (SNI); тост на
  Wayland без позиции/always-on-top (компоунтер игнорирует). Bind-пробы (v7) на
  Linux не создаются — `cfg!(windows)`-гейт: эти клавиши приходят через egui как
  обычные key-события, и ловить их системным grab было бы вредно. Чужой X11-grab
  вытеснить нельзя, поэтому повтор регистрации при фокусе окна просто
  воспроизводит ту же ошибку (§4.1).
- **Win11: PrintScreen и Snipping Tool — две разные проблемы, два разных
  механизма.**
  *Комбо занята другим клиентом:* bare PrintScreen может принадлежать системному
  дефолту (Snipping Tool); при получении окном настроек фокуса выполняется
  повторная регистрация (§4.1) — на Windows foreground-окно может забрать такое
  комбо; если не помогло — отключить настройку ОС или перепривязать хоткей в UI.
  *Нажатие не доставляется:* даже с отключёнными нашими хуками Windows не
  присылает в egui нажатия `PrintScreen`/`ScrollLock`/`Pause` — для
  `VK_SNAPSHOT` нет `WM_CHAR`/`WM_DEADCHAR`, winit 0.30.13 откладывает keydown до
  char-сообщения и сбрасывает сохранённый `PartialKeyEventInfo` на следующем
  keydown (`platform_impl/windows/keyboard.rs:106-155`, `:124-125`); апстрим-фикс
  после 0.30.13 не существует. Обход (v7) — временные пробные регистрации на
  время keyboard-capture (§4.4): выстрел пробной комбо пишет бинд вместо
  скриншота. Цена: Snipping Tool не срабатывает, пока строка в capture; в
  простое — без изменений.
- **Windows-runtime приёмка bind-пробы (отложена, v7):** доказано пока —
  юнит-тесты (наборы пробных комб, «проба проверяется раньше карты действий»,
  commit пробного нажатия с сохранением `pad`, round-trip `ScrollLock` через
  `parse_key`) плюс compile/clippy/release-сборка `x86_64-pc-windows-gnu`.
  Реальный `RegisterHotKey`-acceptance пробных комб, доставка `WM_HOTKEY` во
  время capture и запись строки проверяются вручную на Windows-машине
  пользователя (§10).
- **Нестандартные кнопки геймпада (Share, Options, paddle-кнопки и т.п.):**
  gameinput-бэкенд отдаёт кнопки как raw-номер; метка читается из device-info
  блока (не через `GetButtonLabel` — такого слота на `IGameInputDevice` в
  vendored header нет), поэтому бинд пишется именем метки (`XboxX`), а
  `unknown:<N>` — только для устройств без меток (§4.1). Индекс стабилен только
  в пределах одной модели геймпада, поэтому имя резолвится в момент выстрела по
  таблицам меток подключённых устройств (первое устройство, отдающее имя);
  legacy gilrs-имена держат фиксированный индекс — это допущение. Имя, которое
  ни одно подключённое устройство не отдаёт, не срабатывает и фиксируется в лог
  одной WARN на имя — отдельного предупреждения в UI нет. Геймпады, которые WGI
  классифицирует как Gamepad (Xbox Series), отдают только канонические кнопки —
  Share на них может не приходить. Xbox Game Bar перехватывает Share (побочный
  запуск Game Bar).
  **Hardware-verification (2026-11-04): пример `buttons.exe` проверен на железе
  пользователя — все ок** (устройство, button bits, Guide/Share приходят).
  Остаток приемки (отложена): virshot с pad-биндом на Windows — выстрел по
  кнопке, capture в UI, нотация метки на реальном железе.
- **Геймпад на Linux — вне scope (аппаратная находка):** `gilrs` не добавлен —
  wgi-бэкенд `gilrs` гейтит чтения по timestamp контроллера, generic
  HID-геймпады отдают константный timestamp, поэтому нажатия не приходят
  (проверено на железе пользователя: pad vendor=1118 product=2835). На Linux
  геймпад-триггер не работает, поле `pad` в UI — disabled placeholder.
- **Связывание клавиш в UI — subset (§4.4):** связывается пересечение кодов,
  которые egui отдаёт как `Event::Key`, и которые `global-hotkey` регистрирует на
  Windows (`SUPPORTED_KEY_NAMES`), плюс клавиши из пробного списка `PrintScreen`
  / `ScrollLock` / `Pause` — они не приходят в egui на Windows и связываются
  через временную bind-пробу (§4.4, v7). Clipboard-комбо
  `Ctrl+Insert` / `Shift+Insert` / `Shift+Delete` обрабатываются egui-winit как
  clipboard-команды до `Event::Key` и в capture не приходят (такой бинд задаётся
  правкой `config.toml`). Модификатор `Super`/`Win` из capture недостижим (winit
  не отдаёт Super — пробные комбы с Win не регистрируются). Локи
  `CapsLock`/`NumLock` (переключают системное состояние), `Fn`/`FnLock` и коды
  без физического кода отвергаются; `Escape`/`Backspace` —
  `bindings::Error::ReservedKey` (§2).
- **Chrome окна (§4.4):** `ViewportBuilder::with_minimize_button(false)` /
  `with_maximize_button(false)` действует только Windows-бэкенд winit; на
  X11/Wayland флаги игнорируются, поэтому в UI-приёмке на Linux отсутствие
  minimize/maximize кадром не подтверждается.
- **Высота содержимого (§4.4):** строка `Apply | OK | Cancel` dock'ается
  нижней панелью (`egui::Panel::bottom`), контент — `CentralPanel`; слишком
  высокое содержимое вкладки обрезается вместо скролла (scroll-контейнер не
  добавлен — YAGNI).
- **Windows — mouse passthrough не поддерживается:** `set_cursor_hittest(false)`
  (winit 0.30.13) добавляет `WS_EX_LAYERED` без `SetLayeredWindowAttributes`,
  окно без layered-атрибутов не композитится, поэтому click-through на Windows
  игнорируется в обоих бэкендах оверлея (см. §4.3). Плашка не интерактивна —
  потеря passthrough безвредна; клики в игру на Windows не проходят.
- **Transparency на Windows — hint, не гарантия:** известная проблема
  прозрачных child-viewports на glow (egui#8423); после снятия `WS_EX_LAYERED`
  (gate click-through выше) прозрачные плашки композитируются DWM.
  `ContentProtected` на ре-композитированном окне — **Needs Windows-verification**
  (приемка на железе пользователя).

### 9.x Сборка Windows (доработки v3)

- subsystem `WINDOWS` (без чёрного окна консоли при запуске):
  `link-args=-Wl,--subsystem,windows` для mingw в `.cargo/config.toml`.
  CLI `virshot shot` пишет stdout только при запуске из уже открытой консоли
  (cmd/PowerShell); двойной клик — без консоли, молча.

## 10. Тестирование и поставка

- **Юнит-тесты:** шаблон пути, санитизация, валидация, парсинг/дефолты конфига.
- **Юнит-тесты i18n (v9):** форма каталога — один файл `locales/app.yml` с
  `_version: 2`; полнота всех шести локалей на всех 76 ключах; целостность
  `%{...}`-плейсхолдеров во всех локалях; рендер всех локалей без
  dotted-fallback и fallback-проба на неизвестной локали (`de` → `en`); пин
  оригинальных английских строк под `en`; равенство встроенного
  (`include_str!`) каталога файлу на диске byte-for-byte. Локализованный чип
  тоста (`capture::saved_text` / `chip_text`) против английского `Error:
  Display`; метки меню трея под текущей локалью и их пересборка на Apply.
  `language`: дефолт `en`, partial TOML, снисходительная нормализация
  (неизвестное значение → `en`, остальные настройки целы), mapping кодов,
  round-trip при сохранении. Покрытие — `src/i18n.tests.rs`, `src/gui.tests.rs`,
  `src/tray.tests.rs`, `src/capture.tests.rs`, `src/config.tests.rs`; тесты,
  тронувшие локаль, сериализуются через static mutex в каждом тест-файле —
  `rust-i18n` кэширует локаль на потоке.
- **Счёт тестов (2026-11-06):** 392 юнит + 9 e2e (root package; e2e с реальным
  дисплеем — ignored на headless-хосте).
- **Интеграция (WSL):** headless `virshot shot` — реальный захват/запись файлов.
- **Приемка на Windows:** вручную, чеклист выдаётся в чате (не в репозитории).
